■ 0. この指示書について
------------------------------------------------------------------------

◆ 0.1 目的

本書は、ブラウザで遊べる横スクロールシューティングゲーム『AETHER LANCE』を、追加の質問なしで最高品質のまま完成させるための設計・実装指示書である。仕様上の判断はすべて本書の中で決めてある。実装者は本書に従って作り、本書に書かれていない細部は「§0.6 判断に迷ったときの優先順位」に従って決める。

◆ 0.2 作品の位置づけ

・1980年代後半から90年代のアーケード横スクロールSTG（『グラディウス』に代表されるジャンル）の手触りを、現代のブラウザ技術で作り直す。目指す手触りは次の4つ。
  ・地形との駆け引き
  ・パワーアップで自機を育てる楽しさ
  ・敵配置を覚えて上達する快感
  ・画面を圧倒する巨大ボス
・特定作品の再現や移植ではなく、完全なオリジナル作品とする。 名称、キャラクター、ステージ、ボス、楽曲、システム上の固有要素は一切流用しない（→ 01 §5 IPガイドライン）。

◆ 0.4 用語と単位

| 用語・記号 | 定義 |
|---|---|
| f（フレーム） | ゲームロジックの1ステップ = 1/60秒。時間に関する数値は原則 f で表す（60f = 1秒） |
| px | 内部解像度（480×270）上の1ピクセル。実画面のピクセルではない |
| px/f | 速度。1フレームあたりの移動ピクセル数 |
| 座標系 | 原点は画面左上。x は右が正、y は下が正 |
| 角度 | 0° = 右（自機の前方）。y軸が下向きなので、時計回りが正（90° = 真下、−90° = 真上、180° = 左） |
| ワールド座標 / スクリーン座標 | 地形はワールド座標で定義し、カメラのスクロール量を引いてスクリーン座標にする。敵・弾・自機は特記がない限りスクリーン座標で管理する（→02 §6） |
| HP / ダメージ | 敵の耐久値。基準はPULSE Lv1の1発 = 1.0 ダメージ |

| キャリア | 倒すとアイテムを落とす敵。アイテムの色で発光する（→03 §5.6） |
| テレグラフ（予告） | 危険な攻撃の前に出す視覚・聴覚の予兆 |
| 周（ループ） | 全6ステージを1巡すること。2周目は難度が上がる |

◆ 0.6 判断に迷ったときの優先順位

本書に書かれていない細部は、上から順に優先して決める。

1. フェアネス: 初見でも、予告を見て反応すれば避けられること。理不尽な死はあってはならない
2. レスポンス: 入力してから画面に反映されるまでの遅延を最小にする。操作感を損なう演出はすべて削る
3. 視認性: 敵弾、自機、当たり判定が、どの背景の上でも一目で分かること
4. 手応えと爽快感: ヒット、撃破、取得のたびに、音・光・揺れのフィードバックを返す
5. 美しさ: スクリーンショット1枚がそのまま宣材として通用する画作り
6. 実装の単純さ: 1〜5に差が出ないなら、単純な実装を選ぶ

◆ 0.8 変更管理

・本書の数値は初期値であり、バランス調整で変えてよい。ただし数値はすべて src/data/balance.ts などのデータファイルに集約し、コード中に直書き（マジックナンバー）しない。
・調整で数値を変えたら、本書の該当表も同じコミットで更新する。
・仕様そのものを変えるとき（システムの追加・削除）は、本書を先に更新してから実装する。

■ 2. デザインピラー
------------------------------------------------------------------------

すべての仕様判断は次の5本柱に照らして行う。

◆ ピラー1「撃つ気持ちよさ」

・弾が当たると、敵が白く光り、乾いたヒット音が鳴り、小さな火花が飛ぶ。どんなに小さな手応えも省略しない。
・敵を倒すと、爆発、破片、スコア表示、効果音、画面の微振動で応える。大物ほど派手にする。
・自機の発射は入力したその同じフレームで行う。待たせる演出は入れない。

◆ ピラー2「組み立てる楽しさ」

・武器タイプ（3種）× 武器Lv（5段階）× サブ武器（2種）× ドローン数（0〜4）× ドローン陣形（3種）× 速度（4段階）を組み合わせて、自分好みの機体構成を作る。
・どの構成にも得意と不得意がある。「全部入り」の正解は作らない（PULSEは単体火力、FANは範囲、RAYは貫通。WINGは前方集中、TRAILは自在な配置、ORBITは防御）。

◆ ピラー3「覚えて上達する」

・敵の配置、アイテムの配置、ボスのパターンはすべて固定（決定的）。死んだ場所を覚えれば次は越えられる。
・乱数を使うのは演出（パーティクルなど）と、シード固定の「揺らぎ」だけ。同じ入力をすれば必ず同じ展開になる。

◆ ピラー4「地形と踊る」

・地形は障害物であると同時に、攻略の手段でもある。地形を這うボム、結晶で反射するRAY、壁に潜むタレットなどがある。
・ステージごとに地形の性質を変える（反射する結晶、再生する肉壁、リズムで出現する壁など）。

◆ ピラー5「一枚絵の美しさ」

・低解像度のピクセルアートに、加算合成の光、ブルーム、多重スクロールを重ねて、現代的に美しく見せる。
・ただし美しさは視認性より下に置く。敵弾は必ずすべての上に、最も目立つ色で描く。

■ 3. 世界観とストーリー
------------------------------------------------------------------------

◆ 3.1 背景設定

・時代: 環暦（Ring Era）412年。人類は惑星「セレス・ミラ」を取り巻く巨大な軌道居住環「ハロー・リング」で暮らしている。
・敵: 太陽系の外縁から飛来した、自己増殖する機械群体「オルド（ORDO）」。オルドの個体どうしは「歌」と呼ばれる振動波で意思を統一している。歌の発信源が、中枢「コーラス・コア（Choir Core）」である。オルドは星系内の天体を次々と侵食し、自らの工廠や巣に作り変えていく。
・自機: 人類最後の試作迎撃機「AL-7 ケストレル（KESTREL）」。機首には収束エーテル砲「ランス」を、随伴機には自律ドローン「ウィスプ」を備える。オルドの歌を一時的に乱す「ランスドライブ」機構を持つ唯一の機体であり、単機で中枢を目指す。
・語り口: 説明しすぎない。ステージ開始時の1行ブリーフィングと、エンディングのごく短いテキストだけで語る。カットシーンは入れない（テンポを優先する）。

◆ 3.2 ステージの物語

◆ 3.3 エンディング

・1周目クリア（通常エンディング）: コーラス・コアが光に崩れ、オルドの歌が止む。ケストレルは夜明けのハロー・リングへ帰還する（ステージ1の惑星背景を朝の色に変えて再利用する）。続いてスタッフロール。最後に「LOOP 2 —— THE SONG REMAINS」と表示し、2周目へ進むかタイトルへ戻るかを選ばせる。
・2周目クリア（真エンディング）: 止んだ歌の代わりに、ハロー・リングの人々が灯す光がリング全周に広がる。テキスト「歌は終わらない。今度は、私たちが歌う。」 / "The Song goes on. This time, we sing it." ORDEALが解放される。
・エンディングとスタッフロールは合わせて90秒以内。スキップは確認ダイアログを出したうえで許可する。

■ 4. トーン＆マナー
------------------------------------------------------------------------

・ビジュアル: 寒色の宇宙に暖色の光。ステージごとに支配色を変え、一目でどのステージか分かるようにする（→07 §2）。
・サウンド: FM音源とPSG音源の中間のような、厚みのあるチップチューン。メロディアスで疾走感があり、ボス戦は緊迫感を重視する（→08）。
・テキスト: 英語の大文字ロゴと、短い日本語の副題を組み合わせる。ミリタリーSF調だが、硬くなりすぎないようにする。
・ゴア表現なし。 敵はすべて機械か、機械と融合した生体。爆発は光と金属片で表現する。

■ 5. IPガイドライン［MUST］
------------------------------------------------------------------------

◆ 5.1 原則

・本作は既存作品のジャンル的な魅力を参考にしたオリジナル作品である。既存作品の表現そのもの（固有の名称・意匠・構成・音楽）は使わない。
・画像と音声はすべて本プロジェクトのコードで生成するか、新規に制作する。外部の素材（画像、音源、サンプル、ROM由来データ）は一切使わない。
・例外として、フォントだけは SIL Open Font License の Google Fonts「DotGothic16」を使ってよい。

◆ 5.2 使ってよい「ジャンル共通の慣習」

・横方向の強制スクロール、地形との接触でミスになるルール
・敵を倒してアイテムを得るパワーアップ、自機に追従・随伴する補助機
・地上の砲台、編隊を組む敵、中ボスと巨大ボス、ボス出現前の警告演出
・残機制、スコアによるエクステンド、周回で上がる難度、撃ち返し弾

◆ 5.3 使ってはならないもの

・既存作品の名称、ロゴ、自機名、敵名、ステージ名、およびそれを連想させるもじり
・既存シリーズを象徴する固有のシステム。特に「パワーアップの項目をゲージ上で選んで取得する方式」は採用しない。本作はクリスタルを取ると即時に強化される方式と、回転チップによる武器タイプ選択で差別化する（→03 §5）
・既存作品を象徴する敵・ボスの意匠（例: 石像の顔の群れ、コアを遮蔽板で守る戦艦型ボスの直接的な模倣、炎を吐く竜の骨格など、特定作品の看板になっている造形）
・既存楽曲のメロディ、リフ、特徴的なコード進行の引用。音声アナウンス（合成音声による武器名の読み上げなど）
・ステージ構成の模倣（特定作品のステージ順や、名物ギミックの順番どおりの再現）

◆ 5.4 チェック手順

各マイルストーンの完了時に、新たに追加した名称・意匠・楽曲について「特定作品の固有要素の模倣になっていないか」を確認し、10 §5 のQAチェックリストにチェックを付ける。

■ 4. ゲームループ
------------------------------------------------------------------------

◆ 4.1 固定タイムステップ

    ----------------------------------------
    const STEP = 1000 / 60;          // 16.666ms
    let acc = 0, last = performance.now();
    function frame(now: number) {
      let dt = now - last; last = now;
      if (dt > 250) dt = 250;          // タブ復帰時などの暴走を防ぐ
      acc += dt;
      let steps = 0;
      while (acc >= STEP && steps < 5) { // 1回の描画で最大5ステップまで追いつく
        input.poll();                  // 1ステップごとに入力スナップショットを確定
        scenes.update();               // ロジック1フレーム
        acc -= STEP; steps++;
      }
      if (steps === 5) acc = 0;        // それでも追いつかなければ捨てる（処理落ちではなくスキップ）
      scenes.render(acc / STEP);       // 補間係数 alpha を渡す
      requestAnimationFrame(frame);
    }
    ----------------------------------------

・補間描画［SHOULD］: 動くエンティティは前フレームの座標 px, py を保持する。描画時は lerp(prev, cur, alpha) を求め、整数に丸めてから描く。オプション「なめらか描画」をOFFにすると、補間せず最新の状態だけを描く。120Hz/144Hzのディスプレイでのカクつきを防ぐための仕組みである。
・ヒットストップとスローモーション: ロジックのステップ数は変えない。ワールド内部の timeScale で表現する。ヒットストップ中は、ワールドのエンティティ更新をスキップするフレームを作る（入力のサンプリング、音、UIは止めない）。スローは「Nフレームに1回だけ更新」という整数方式で実装し、決定性を保つ。
・タブの非表示（visibilitychange）: ゲーム中なら自動でポーズし、AudioContextを suspend する。
・ウィンドウのフォーカス喪失（blur）: 押下中のキーをすべて離した扱いにする（キーが押しっぱなしになる事故を防ぐ）。

◆ 4.2 シーン管理

・SceneStack。push / pop / replace。最上位のシーンだけが update され、transparent フラグを持つシーン（ポーズなど）は下のシーンも描画する。
・シーン遷移は黒フェード（アウト20f、イン20f）。フェード中は入力を受け付けない。
・シーン一覧: Boot、Title、MainMenu、DifficultySelect、PracticeSelect、Options、KeyConfig、Game、Pause（透過）、StageClear（Gameの子状態でもよい）、GameOver、NameEntry、Ranking、Ending、Credits、ErrorScreen。

◆ 4.3 ワールドの更新順序（1フレーム）［MUST: この順序を厳守］

1. 入力スナップショットの取得（held / pressed / released）
2. タイムラインの処理（このフレームのイベントを実行し、敵の出現、スクロール変更、BGM変更などを行う）
3. カメラとスクロールの更新（地形のスクリーン座標を確定）
4. 自機の更新（移動、境界のクランプ、発射の要求）
5. ドローンの更新（陣形の位置、発射）
6. 自機弾の生成と更新
7. 敵の更新（コルーチンを1ステップ進める → 移動 → 発射の要求）
8. 敵弾の生成と更新
9. アイテムの更新（磁力の処理を含む）
10. 衝突判定（順に: 自機弾→地形、自機弾→敵、敵弾→ドローン（ORBIT時）、敵弾→自機、敵本体→自機、地形→自機、アイテム→自機、かすり判定）
11. 死亡と生成のキューを処理（このフレームで死んだものを除去し、爆発を生成）
12. エフェクトの更新（パーティクル、画面の揺れ、フラッシュ、スコアのポップアップ）
13. スコア、ランク、エクステンド、ドライブゲージの更新
14. 音イベントを確定し、オーディオエンジンへ送る（同じフレームに重複したSEはまとめる）
15. prevX/prevY の保存（補間用。各エンティティの更新の冒頭で行ってもよい）

■ 5. エンティティ設計

◆ 5.1 方針

・本格的なECSは採用しない。種類ごとの型付きクラスと、オブジェクトプールで構成する。
・ゲーム中（Gameシーンのupdate/render中）はヒープ確保をゼロにすることを目標とする。クロージャ、配列リテラル、スプレッド構文、文字列の結合、Array.prototype.map/filter をホットパスで使わない。
・プールはエンティティ種別ごとに固定長の配列とし、active フラグとフリーリスト（スタック）で管理する。

| プール | 上限 | 溢れたとき |
|---|---|---|
| 自機弾 | 256 | 最古のものを再利用 |
| ドローン弾 | 256 | 同上 |
| サブ武器（ボム、ミサイル） | 64 | 生成を諦める |
| 敵 | 160 | 生成を諦め、デバッグ時は警告を出す |
| 敵弾 | 1024 | 生成を諦める（デザイン上は600を超えないようにする） |
| アイテム | 64 | 最古のスターチップを消す |
| パーティクル | 2048 | 最古のものを再利用 |
| テキストポップアップ | 64 | 最古のものを再利用 |

◆ 5.3 コルーチン（敵スクリプト）

・敵の行動はTypeScriptのジェネレータ関数で書く。yield n で n フレーム待機する。
・スクリプトのAPI（ScriptCtx）:

| API | 動作 |
|---|---|
| wait(n) | nフレーム待つ（yield n の別名） |
| moveTo(x, y, frames, ease) | 指定したフレーム数で目標座標へ移動する。ease は linear / inQuad / outQuad / inOutSine / outBack |
| moveBy(dx, dy, frames, ease) | 相対移動 |
| setVel(vx, vy) / setPolar(angle, speed) | 速度を設定する |
| accel(ax, ay) | 加速度を設定する |
| aimAngle() | 自機への角度を返す（決定的な atan2 を使う） |
| fire(pattern, params) | 弾幕パターンを発射する（→04 §4）。発射位置は敵の muzzle オフセット |
| telegraph(kind, params, frames) | 予告表示（線、円、点滅）を出す |
| sfx(id) | SEを鳴らす |
| spawn(enemyId, x, y, opts) | 子の敵を生成する |
| whileAlive(partId) | 指定パーツが生きている間ループするための条件 |
| parallel(...gens) | 複数のサブスクリプトを並行して実行する（ボス用） |
| onBeat(n) | 次の n 拍目まで待つ（ステージ6のビート同期用 →08 §6） |

    ----------------------------------------
    // 例: 画面右から入り、停止して自機を狙い撃ち、上方向へ退場する
    export function* dartAmbush(e: Enemy, c: ScriptCtx) {
      yield* c.moveTo(380, e.y, 40, 'outQuad');
      yield 20;
      c.fire('aimed', { speed: 2.2 });
      yield 30;
      c.setPolar(-150, 2.5);
    }
    ----------------------------------------

■ 6. 座標、カメラ、スクロール
------------------------------------------------------------------------

・画面サイズは 480×270。プレイフィールドは画面全体で、HUDは上下に半透明で重ねる。
・カメラ はワールド座標上の camX, camY を持つ。通常のステージは camY = 0 で固定し、camX をスクロール速度で増やす。
・スクロールベクトル scrollVX, scrollVY（px/f）はタイムラインで変更でき、指定フレーム数をかけて ease で補間する。ステージ5の縦スクロール区間では scrollVY ≠ 0 になる。
・縦カメラ追従［SHOULD］（ステージ2の分岐区間）: ワールドの高さが画面より高い区間では、自機のy座標に応じて camY を追従させる。デッドゾーンは画面中央±50px、追従速度は差分×0.08/f、最大2px/f。
・敵、弾、自機はスクリーン座標で管理する（スクロールの影響を受けない）。地形に固定された敵（GROUND フラグ）だけは、毎フレーム「アンカーのワールド座標 − カメラ」で位置を決める。
・画面外のマージン: 敵は画面外64pxまで生存する（PERSISTENT 以外）。敵弾は16pxを超えたら消滅させる。

■ 7. 衝突判定
------------------------------------------------------------------------

◆ 7.1 形状

| 対象 | 形状 | 値 |
|---|---|---|
| 自機（弾・敵に対する判定） | 円 | 半径 2.0px。中心はスプライト中心から (+3, 0)（コクピット） |
| 自機（地形に対する判定） | AABB | 16×6px、スプライト中心基準 |
| 自機（かすり判定） | 円 | 半径 14px |
| 自機（アイテム取得） | 円 | 半径 12px。磁力範囲は半径 40px |
| 敵本体 | AABB または円（敵定義で指定）。パーツは個別の形状を持つ | — |
| 敵弾 | 円（ニードルはカプセル） | 弾種ごとに →04 §3 |
| レーザー | 線分 + 太さ（カプセル） | — |
| 自機弾 | AABB（PULSE、FAN）、カプセル（RAY） | — |

◆ 7.2 ブロードフェーズ

・敵は32px格子の一様グリッドに登録する（毎フレーム作り直す。セル配列は使い回す）。自機弾は自分が重なるセルの敵だけを調べる。
・敵弾と自機の判定は全数を走査する（自機は1体なので O(n) で十分）。

◆ 7.3 地形との衝突

・地形は16×16pxのタイルで構成する。タイルごとに16行×16bitの衝突マスク（Uint16Array(16)）を持たせ、斜面や曲面をピクセル単位で表現する。
・自機と地形の判定: 地形AABB（16×6）の外周上の12点（各辺3点）と中心の計13点をサンプルし、1点でも固体ならヒットとする。
・弾と地形の判定: 弾の中心点が固体かどうかで判定する。RAYは先端の点で判定する。
・地形の法線（バリア時の押し戻しや、反射に使う）: ヒット点の周囲3×3のマスクから勾配を求める。結晶反射用の法線は、タイルに事前計算した値を使う。
・破壊可能タイル（ステージ2の結晶壁、ステージ3の肉壁）: タイルごとにHPを持つ。破壊したら衝突マスクを0にし、描画はアニメーションで欠けさせる。再生するタイルは、再生時に自機と重なっていたら待機する。

■ 8. 決定性［MUST］
------------------------------------------------------------------------

リプレイ、デバッグ、テストの再現性のために、ゲームロジックは完全に決定的にする。

・乱数: mulberry32 などシード付きのPRNGを使う。ストリームを2系統に分ける。
  ・rngGame: ゲームに影響する乱数（ステージ開始時に seed = stageIndex  7919 + loop  104729 で初期化）
  ・rngFx: 見た目だけの乱数（パーティクル、揺れ）。ゲームロジックから絶対に参照しない
・三角関数: Math.sin / cos / atan2 はエンジンによって結果が異なることがあるので、ゲームロジックでは使わない。四則演算と Math.sqrt（IEEE754で結果が保証される）だけで実装した dsin / dcos / datan2 を core/math/dmath.ts に用意する（多項式近似、誤差1e-6以下）。描画やパーティクルでは Math.* を使ってよい。
・時間: ゲームロジックの中では performance.now() や Date を参照しない。フレーム数だけを使う。
・反復順序: プールの走査順は固定する（配列のインデックス順）。Map や Set の反復は挿入順なので使ってもよいが、オブジェクトキーの列挙に依存しない。
・検証: 入力ログを2回再生し、各ステージ終了時のワールド状態のハッシュ（自機の座標、スコア、敵の数、乱数の状態）が一致することを単体テストで保証する（→10 §3）。

■ 9. 入力システム
------------------------------------------------------------------------

・アクション写像: 物理入力（キー、ボタン、タッチ）を論理アクションに変換する。ゲームのコードは論理アクションだけを参照する。
・論理アクション: UP, DOWN, LEFT, RIGHT, SHOT, DRIVE, SPEED_UP, SPEED_DOWN, FORMATION, PAUSE, CONFIRM, CANCEL、および SPEED_1〜4（キーボード専用の直接指定）。
・短い押下の取りこぼし防止: keydown/keyup はイベント時点でキューに積み、次のロジックフレームで pressed に確定する。同じフレーム内で押して離した場合も pressed = true として扱う。
・KeyboardEvent.code を使う（キーボードレイアウトに依存させない）。ゲーム中は方向キーやスペースの preventDefault を行い、ページのスクロールを防ぐ。
・ゲームパッド: 毎フレーム navigator.getGamepads() をポーリングする。Standard Mapping を前提とし、非標準のパッドもキーコンフィグで割り当てられるようにする。
・タッチ: Pointer Events で実装する（→03 §2.3、09 §6）。
・操作の詳細は 03 §2 を参照。

■ 10. 描画パイプライン
------------------------------------------------------------------------

1. ゲームcanvas（480×270、オフスクリーン） にCanvas2Dで描画する。imageSmoothingEnabled = false。描画順は 07 §8 のレイヤ表に従う。
2. 発光バッファ（240×135、半解像度）［SHOULD］: 加算発光が必要なもの（弾のグロー、爆発、レーザー）を別にも描く。WebGLのブルーム入力に使う。
3. プレゼンテーション:
   ・WebGL2がある場合: ゲームcanvasをテクスチャにアップロードし（texSubImage2D）、ブルーム → CRT/歪み → 拡大の順にシェーダを通して表示canvasへ描く（→07 §7）。
   ・WebGL2がない場合: 表示canvasに drawImage で整数倍に拡大して描く（nearest）。
4. UIオーバーレイcanvas（実ピクセル解像度）: 日本語テキスト、タッチボタン、メニューの説明文など、高解像度で描くべきものを描く。ゲーム画面と同じ位置・サイズに重ねる。
5. スケーリング: オプションで INTEGER（既定。最大の整数倍）、FIT（アスペクト比を保って最大化、nearest）、STRETCH を選べる。余白は黒にする。devicePixelRatio を考慮し、CSSピクセルではなく実ピクセルで整数倍にする。

■ 11. 音声
------------------------------------------------------------------------

詳細は 08_audio.md。要点は次の3つ。

・AudioContext は最初のユーザー操作（クリック、タップ、キー入力）で生成・resumeする。Bootシーンに「CLICK / TAP / PRESS ANY KEY」を表示して、この操作を促す。
・SEはブート時に OfflineAudioContext で AudioBuffer に事前レンダリングする［SHOULD］。BGMはリアルタイムに合成する。
・ゲームロジックからは audio.play(sfxId, {x}) と audio.music(songId, opts) だけを呼ぶ。

■ 12. セーブ

・スキーマとマイグレーションは 09 §8 を参照。

■ 13. エラー処理
------------------------------------------------------------------------

・window.onerror と unhandledrejection を捕捉し、ErrorScreen を表示する。内容は「エラーが発生しました」、エラーの要約、スタックをコピーするボタン、タイトルへ戻るボタン。

・各ステージのデータはブート時に検証関数（validateStage）を通す。未定義の敵IDや範囲外の値があれば、開発時は即座に例外を投げる。

・PWA［SHOULD］: manifest（display: fullscreen、orientation: landscape、テーマ色 #0b0d17）、アイコン（192/512。ケストレルのシルエット）、Service Worker（全ファイルをプリキャッシュし、オフラインで動作させる）。iPhoneではFullscreen APIが使えないため、ホーム画面への追加（standalone）でフルスクリーンにする。
・外部への通信は Google Fonts（DotGothic16）だけにする。フォントの読み込みに失敗しても、ビットマップフォントとシステムフォントにフォールバックして動作させる。単一HTML版では、DotGothic16を使用文字だけサブセット化し、base64のwoff2として埋め込んでもよい［COULD］。

■ 15. パフォーマンス予算
------------------------------------------------------------------------

| 項目 | 予算（基準機） |
|---|---|
| ロジック1フレーム | 3ms以下（最大負荷のボス戦で5ms以下） |
| 描画1フレーム | 7ms以下（ポストエフェクト込み） |
| GC | ゲーム中にメジャーGCが起きないこと（ヒープの増加量 < 100KB/分） |
| 起動 | ブートからタイトル表示まで1.5秒以内（スプライトのアトラス生成とSEの事前レンダリングを含む） |
| サイズ | JS gzip後で400KB以下 |
| 自動品質調整 | 平均fpsが55を下回る状態が2秒続いたら、①パーティクルの生成数を半分にし、②ブルームを1/8解像度に落とし、③CRTを無効にする（段階的に適用し、回復しても戻さない）。オプションで手動設定もできる |

■ 16. コーディング規約
------------------------------------------------------------------------

・ESLint の推奨ルール + @typescript-eslint/recommended-type-checked。any は禁止（境界部では unknown と型ガードを使う）。
・ゲームの数値はすべて balance.ts や各コンテンツの定義に置く。
・1ファイル600行以内を目安にする（ボススクリプトは例外として1000行まで認める）。
・状態は World が所有する。グローバルな可変状態を作らない（シングルトンは audio、input、storage だけ）。
・コミットはマイルストーンのタスク単位で行い、メッセージは英語の命令形にする。

■ 3. 自機「AL-7 KESTREL」
------------------------------------------------------------------------

◆ 3.1 基本仕様

| 項目 | 値 |
|---|---|
| スプライト | 30×14px（右向き）。デザインは →07 §4.1 |
| 当たり判定 | 円 r=2.0（コクピット位置。中心から +3, 0） |
| 地形判定 | AABB 16×6 |
| 耐久 | 1発でミス（バリアがあれば3回まで防げる） |
| 慣性 | なし。入力した瞬間に最高速で動き、離した瞬間に止まる |
| 初期速度Lv | 2 |

◆ 3.2 速度レベル

| Lv | 速度（px/f） | エンジン炎の長さ | 用途 |
|---|---|---|---|
| 1 | 1.6 | 4px | 精密な回避、狭い地形 |
| 2 | 2.2 | 7px | 標準 |
| 3 | 2.8 | 10px | 機動戦 |
| 4 | 3.4 | 13px | 高速の敵、広い回避 |

・切り替えは即座に反映する。切り替えのとき、自機の後方に残像を3枚出し（8f）、SE speed_change を鳴らし、HUDの速度ゲージを点滅させる。
・ミスすると速度はLv2に戻る。

◆ 3.3 アニメーション

・バンク（傾き）: 上下入力を4f続けると「傾き1」、12f続けると「傾き2」のフレームに切り替わる。入力をやめたら4fごとに1段階ずつニュートラルへ戻る。
・エンジン炎: 4フレームのアニメーションを2fごとに切り替える。長さは速度Lvに比例する。前進入力中は+3px、後退入力中は−2px。
・発射時: 機首にマズルフラッシュ（2f）。

◆ 3.4 出撃、ミス、復活

1. ステージ開始: 自機は x=−20 から x=80, y=135 まで、45fかけて ease-out で進入する（この間は操作できない）。
2. 被弾: 
   ・そのフレームからヒットストップ6f（演出以外の全停止）。
   ・自機の大爆発（→07 §6.3）、画面の揺れ（trauma +0.5）、SE player_die。BGMは60fのあいだ −6dB にダッキングする。
   ・画面上の全敵弾を消去する（12fかけて溶けるように消す。スコアは入らない）。
3. 復活待ち（120f）: タイムラインはそのまま進む。この間と次の進入中、敵は発射しない（弾を生成しない）。
4. 残機の判定: 残機が0ならゲームオーバーへ。残っていれば1減らす。
5. 再進入: x=−20 から x=60, y=135 まで40fかけて進入する（操作不可）。操作できるようになってから120fのあいだ無敵（4fごとに点滅）。無敵中もショットと移動はできる。
6. ミス時のペナルティ（その場復活ルール。NORMALの場合）:

| 要素 | 処理 |
|---|---|
| メイン武器Lv | −1（最低1）。EASYは減らさない、HARDは−2、ORDEALはLv1に戻す |
| 武器タイプ | 維持 |
| サブ武器 | Lv2ならLv1へ、Lv1なら維持（ORDEALでは失う） |
| ドローン | 全機が「ロスト・ウィスプ」アイテムとして散らばる（→§5.4）。触れれば回収できる |
| バリア | 消失 |
| 速度 | Lv2に戻る |
| ドライブゲージ | 半分になる |

7. CHECKPOINTルール（難易度選択時にオプションで選べる）: ミスすると直前のチェックポイント（各ステージに3か所: 開始、中間、ボス直前）から再開する。装備はすべて失う（Lv1、PULSE、サブなし、ドローン0、速度2）。チェックポイントからの再開時は、そのチェックポイント以降のタイムラインを最初から実行し直す。上級者向けのクラシックなルールで、ハイスコアの記録は「CP」と区別して表示する。

■ 4. メイン武器
------------------------------------------------------------------------

◆ 4.1 共通

・武器タイプは3種類: PULSE（パルス）、FAN（ファン）、RAY（レイ）。
・Lvは全タイプで共通（1〜5）。タイプを切り替えてもLvはそのまま。
・ショットボタンを押している間、各武器の発射間隔で自動連射する。押した瞬間はクールダウンが明けていれば即座に撃つ。
・ショット1発ごとにSEを鳴らす。ただし音量を抑え、同じSEは4fに1回までにする（→08 §7）。
・ドローンも同じ武器を、同じタイミングで撃つ（威力倍率 →§5.3）。

■ 8. 動的ランク
------------------------------------------------------------------------

・内部値 R（0〜100）で、敵の攻撃の強さを調整する。プレイヤーには表示しない（デバッグ表示では見える）。
・R = clamp(R_base + R_time + R_power, 0, R_max)
  ・R_base: 難易度ごとの初期値（→§10）
  ・R_time: 10秒生き延びるごとに +0.5（上限30）。ミスで −15（下限0）。
  ・R_power: (メインLv − 1)×4 + ドローン数×3 + (サブあり ? 3 : 0) + (バリアあり ? 2 : 0)。毎フレーム再計算する。
・敵への反映:

| 要素 | 計算式 |
|---|---|
| 敵弾の速度倍率 | 1 + R×0.003（R=100で×1.3） |
| 敵の発射間隔の倍率 | 1 − R×0.003（R=100で×0.7） |
| n-way弾の追加 | R ≥ 70 で +2発（パターン定義で scalable: true のものだけ） |
| 撃ち返し弾 | HARDでR ≥ 50、ORDEALと2周目は常時（→04 §5） |

■ 11. フェアネス規則［MUST］
------------------------------------------------------------------------

1. 敵は画面に入ってから 20f は発射しない。
2. 敵弾は、自機から 40px以内 の位置には生成しない（その弾は生成をスキップする）。
3. 自機狙いの弾を撃つ敵は、自機より左（後方）に来たら狙い撃ちしない（frontOnly の既定値は true）。
4. 自機の後方（画面左）から現れる敵は、出現の60f前に、画面左端の該当するy位置に赤い矢印「◀!」を点滅表示し、SE warn_behind を鳴らす。
5. 致死性のギミック（レーザー、雷、プレス、溶鉄、壁の出現）には必ず予告を出す。予告の長さは、NORMALで最低 40f（HARDで30f、EASYで60f）。
6. ミスした瞬間に敵弾を全消去し、復活シーケンス中は敵が発射しない（→§3.4）。
7. 回避できない配置を作らない。各ボスパターンは「その場に留まらず、正しく動けば必ず避けられる」ことを、デバッグのリプレイ（→10）で検証する。
8. スクロールで地形と画面左端の間に挟まれたらミスになる（EASYは押し戻し）。ただし、挟まれる 60f前 から地形の縁を赤く点滅させる。
9. 背景のオブジェクトは敵弾の色系統（マゼンタ〜ピンク〜橙）を広い面積で使わない（→07 §2.2）。
10. 画面外（左右16px以内）から急に高速で飛び込む敵弾は撃たない（敵の発射位置は画面内に限る）。

04. 敵・弾仕様
========================================================================

■ 1. 敵の共通仕様
------------------------------------------------------------------------

◆ 1.1 被弾と撃破

・ヒットフラッシュ: 被弾したフレームから2f、スプライトを白一色のシルエットに置き換える。連続で被弾しているときは、2f白・2f通常を交互に繰り返す（白のままになってしまうのを防ぐ）。
・ヒット音: hit_enemy（装甲に当たったときは hit_armor）。同じ敵に対しては4fに1回までにする。
・ダメージの見た目: HPが30%を下回ると、8fごとに黒煙のパーティクルを出す。中型以上の敵は火花も出す。
・撃破: 敵のサイズクラスに応じた爆発（→07 §6.3）、基本点の加算、スコアのポップアップ（中型以上と、至近距離ボーナス時のみ表示）、ドライブゲージの加算、キャリアならアイテムの放出。
・装甲（ARMORED）: 自機弾がダメージを与えずに消える。小さな火花と hit_armor。RAYも止まる。

◆ 1.2 出現と退場

・出現位置は、画面外（右端なら x = 480 + 幅/2 + 4）を基本とする。
・PERSISTENT でない敵は、画面外へ64px以上出たら消える（撃破扱いにはならず、編隊ボーナスも成立しない）。
・地上の敵（GROUND / CEILING / WALL）は地形のアンカーに固定され、地形と一緒にスクロールする。天井の敵はスプライトを上下反転して使う。

◆ 1.3 サイズクラス

| クラス | 目安のサイズ | 爆発 | ドライブ | 画面の揺れ |
|---|---|---|---|---|
| S（小型） | 〜20px | small | +1 | なし |
| M（中型） | 20〜48px | medium | +4 | +0.15 |
| L（大型・中ボス） | 48px以上 | large | +6 | +0.35 |
| BOSS | — | boss | — | 1.0（撃破時） |

◆ 1.4 発射規則

・03 §11 のフェアネス規則に従う。
・発射間隔と弾速は、難易度とランクの倍率を適用したうえで、整数フレームに丸める。
・発射が決定的であること: 「何番目の敵が撃つか」は編隊の中のインデックスで決める（例: fireMask: 0b10100 なら3番目と5番目が撃つ）。乱数では決めない。

■ 3. 敵弾
------------------------------------------------------------------------

◆ 3.1 視認性の規則［MUST］

・敵弾はマゼンタ〜ピンク〜橙の系統の色と、白い芯で描く。この色系統は、背景で広い面積に使ってはならない（→07 §2.2）。
・すべての敵弾には、1pxの暗いアウトライン（#2a0614）を付ける。明るい背景の上でも浮き上がらせるため。
・敵弾は自機弾、爆発、地形より上のレイヤーに描く（HUDとUIの下）。
・敵弾は常にアニメーション（回転か脈動）させ、背景の静止物と区別できるようにする。
・当たり判定はスプライトの見た目より小さくする（下表）。

■ 4. 弾幕パターンライブラリ（game/patterns.ts）
------------------------------------------------------------------------

すべてのパターンは純粋関数とし、(origin, params, rank, difficulty) → 弾の生成命令 を返す。生成した弾は敵弾プールに入れる。

| パターン | パラメータ | 内容 |
|---|---|---|
| aimed | speed, kind | 自機狙いの1発 |
| aimedBurst | count, interval, speed, kind | 自機狙いの連射（1発ごとに狙い直す） |
| aimedStream | count, interval, speed | 最初の1発の角度に固定した連射 |
| nway | n, spread, speed, baseAngle（未指定なら自機狙い）, kind, scalable | 扇形 n-way。奇数なら中央の弾が自機を狙い、偶数なら自機を外す |
| ring | n, speed, startAngle, kind | 全方位のリング |
| ringGapped | n, speed, gapAngle, gapWidth | 隙間のあるリング（隙間は自機の方向や、固定の方向に開ける） |
| spiral | arms, rotPerShot, interval, duration, speed | 渦巻き。腕の数と回転速度で形を変える |
| flower | n, speed, accel, turn | 曲線を描く弾（毎フレーム turn°ずつ角度を変える） |
| wall | count, spacing, speed, angle, gapIndex | 弾の壁。抜け穴が1か所ある |
| laser | from, angle, width, telegraph, duration, reflect | レーザー（反射の計算は地形と結晶タイルを使う） |
| laserSweep | from, angleStart, angleEnd, frames | 予告のあと、指定角度の範囲を掃射する |
| bolt | x, telegraph | 縦方向の落雷（ST4） |
| waveArc | angle, width, gaps[] | 音波の弧（ST6） |
| noteBullets | noteEvents | BGMの音符イベントの音高を角度に写像して撃つ（ST6最終ボス →06） |

・scalable: true のパターンは、ランクと難易度による弾数の増減（→03 §8、§10）を受ける。
・すべてのパターンは発射時に sfx を指定できる（既定は enemy_fire_s）。

■ 5. 撃ち返し弾
------------------------------------------------------------------------

・条件: HARDでランク50以上、ORDEAL、2周目（EASYを除く）。
・S・Mクラスの敵が撃破されたとき、その位置から自機狙いのPELLET（速度1.6×ランク倍率）を1発撃つ。
・例外（撃ち返さない）: 自機から64px以内で撃破されたとき、撃破時の位置が自機より左だったとき、画面の右端16px以内だったとき、MOTHとSPORE。
・撃ち返す敵は、撃破の瞬間に一瞬だけ赤く光らせる（プレイヤーが学習できるように）。

■ 8. 地形の制作方法
------------------------------------------------------------------------

・地形は「地形セグメント」の列で記述し、ロード時に16×16タイルの列（高さ17タイル = 272px。縦カメラのある区間はそれ以上）へ変換（ベイク）する。手作業で長いASCIIマップを書かない。
・セグメントの型（→11 §2）:

| 型 | パラメータ | 内容 |
|---|---|---|
| none | length | 地形なし |
| floor | length, height, [rough] | 床（下からの高さ。rough は凹凸の振幅） |
| ceil | length, height | 天井 |
| corridor | length, floorH, ceilH | 床と天井 |
| ramp | length, from, to, which | 床か天井の高さを線形に変える（斜面タイルを自動で選ぶ） |
| pillars | length, interval, width, gap, alternate | 交互の柱 |
| islands | length, list | 浮遊する島（ST4） |
| breakable | x, y, w, h, hp, regen? | 破壊可能なブロック（ST2の結晶、ST3の肉壁） |
| crystal | x, y, w, h | 反射面のタイル |
| conveyor | x, y, w, which, speed | コンベア |
| rhythm | x, y, w, h, phase | 共鳴する壁（ST6） |
| wave | length, amp, period | 蠕動する壁（ST3。描画と判定を毎フレーム、オフセットで動かす） |

・オートタイリング: 固体タイルの4近傍と斜め4近傍から、47種のブロブタイルを自動選択する。タイル画像はステージのテーマごとに手続き生成する（→07 §5）。
・地上の敵のアンカーは「セグメントの開始位置からの相対座標」で指定し、地形の表面の高さに自動でスナップさせる（snap: 'floor' | 'ceil'）。

06. 中ボス・ボス仕様
========================================================================

■ 1. 共通仕様
------------------------------------------------------------------------

◆ 1.1 出現

・中ボス: 警告の演出はない。BGMは道中の曲のまま。登場の60fは無敵で、登場が終わったらHPバーを表示する。
・ボス: WARNING（180f）→ 登場演出（120〜240f。無敵）→ ボスBGM開始 → HPバーを表示する。
・登場演出の途中でも自機は自由に動ける。ボスは登場中に攻撃しない。

◆ 1.2 HPバー

・上HUDのすぐ下（y=14）、中央に幅220px・高さ4pxで表示する。ボス名を小さく左に添える。
・値は「現フェーズでダメージが通る全パーツのHP合計」。フェーズの区切りは目盛りで示す。
・ダメージを受けた分は白く残し、20fかけて減らす（減少アニメーション）。

◆ 1.3 パーツ

・ボスは複数のパーツで構成する。各パーツは hp、armored（常時 / 条件付き）、hitbox、onDestroy を持つ。
・破壊したパーツは「残骸のスプライト」に差し替え、煙と火花を出し続ける（ボス撃破まで）。
・パーツを破壊すると、ヒットストップ4f、medium爆発×3、パーツの点数、画面の揺れ +0.35。

◆ 1.4 フェーズ移行

・HPの閾値またはパーツの破壊で、次のフェーズへ移行する。
・移行時の演出: 60fのあいだ無敵、画面上の敵弾をSTAR CHIPに変える、ボスが赤く明滅する、SE boss_phase、画面の揺れ +0.3。

◆ 1.5 撃破

1. ヒットストップ8f
2. スローモーション60f（3フレームに1回だけ更新する）。画面上の敵弾はすべてSTAR CHIPに変わる
3. 連鎖爆発（ボスの各部位で、medium〜largeの爆発を120fのあいだ6fごとに）。BGMは停止する
4. 最後の大爆発: 白フラッシュ（alpha 0.8 → 0、30f）、画面の揺れ 1.0、ショックウェーブの歪み、SE boss_die
5. ボスの破片（大きな残骸スプライトが回転しながら飛び散る）
6. 撃破点を中央に大きくポップアップ表示し、勝利ジングル jingle_clear を鳴らす → ステージクリアの集計へ

◆ 1.6 時間制限

・制限時間を過ぎたボスは撤退する（画面外へ高速で離脱する）。撃破点とBOSS TIMEボーナスは入らない。中ボスも同様。
・残り10秒になったら、HPバーを点滅させる。

◆ 1.7 HPの設計基準

・想定DPS（NORMAL、標準的な装備、命中率50%で計算）: ST1 約35、ST2 約50、ST3 約65、ST4〜6 約80〜90。
・目標の撃破時間: 中ボス20〜30秒、ボス60〜90秒、最終ボス合計120〜150秒。

| 音波 | 毎小節の1拍目に、自機方向へWAVE ARC（中心角60°）。隙間の位置を左右交互に変える |
| 羽根 | 翼が開く小節の頭に、羽根のNEEDLE 7-way |
| 第2節（HP 50%以下） | 旋律弾を上下対称の2本に、音波を2重に |

・移行: 歌が途切れ、画面が暗転し、音楽が止まる。

形態3「SILENCE（沈黙）」

| 項目 | 値 |
|---|---|
| 構成 | 小さな核（40×40、HP 1500）。高速で動く |
| 音 | BGMはなく、心音だけ（HPが減るほど心拍が速くなる） |
| 特殊ルール | 自機のドライブゲージが毎フレーム+1ずつ自動で増える（100fで満タン）。ドライブ中は、核へのダメージが×2になる。プレイヤーにランスドライブで決着をつけさせる演出 |

| 攻撃 | 内容 |
|---|---|
| 突進 | 予告線（40f）の上を高速で突進する。通った軌跡に4fごとにPELLETを置き、置いた弾は軌跡に垂直な方向へ0.8px/fでゆっくり広がる |
| 決着 | 撃破すると、画面全体が白く染まり、止まっていた音楽が長調の和音で解決する → エンディングへ |

・2周目: 形態1の外輪が毎拍5-wayに、形態2の旋律弾が速度2.2に、形態3の軌跡の弾が2倍に。

■ 1. アートディレクション
------------------------------------------------------------------------

・スタイル: 16bit世代の後期を超える密度の「ハイビット・ピクセルアート」。内部解像度は480×270と低いが、色数を豊富に使い（マスターパレット50色）、加算合成の光、ブルーム、多重スクロールで奥行きと輝きを出す。
・光源: すべてのスプライトで左上からの光に統一する。陰影は基本色ごとに3〜4段階。
・輪郭線:
  ・小さなもの（〜24px）: 暗色の1px輪郭（N1）で背景から浮かせる。
  ・大きなもの（ボスなど）: 部位の色の暗い色で輪郭を付ける（セレクティブ・アウトライン）。
・シルエット優先: 自機、敵、弾は、シルエットだけで種類が分かるように描く。
・色の役割:

| 役割 | 色の系統 |
|---|---|
| 人類側（自機、自機弾、ドローン） | 白、シアン、青 |
| オルド（敵） | 灰色の装甲 + 青緑（T3）の発光部。ステージによって紫、金、有機的な色が加わる |
| 敵弾 | マゼンタ〜ピンク〜橙 + 白い芯（専用の色） |
| 警告、予告 | 橙黄（O5）の点滅 |
| アイテム | 赤、青、緑、金、白、紫（それぞれの意味で固定） |

◆ 2.2 色の使用規則［MUST］

1. R0〜R4は敵弾（とその予告に付随する発光）専用とし、他の用途に使わない。
2. 背景（L0〜L3）と地形では、色相 300°〜30°（マゼンタ〜赤〜橙）で彩度60%以上の色を、画面の5%を超える面積に使わない。ST5の溶鉄の橙は例外とするが、そのぶん敵弾に輪郭R0と白芯を必ず付け、ST5の背景の明度を下げる。
3. 背景の平均明度は、画面の上で敵弾より常に低くする（目安: 背景レイヤーの明度は最大70%。明るい雲や光の背景は、ポストエフェクトの前に bgDim を掛ける）。
4. グラデーションはパレットに量子化し、4×4のBayerディザで階調を表現する（ピクセルアートの質感を保つ）。

◆ 3.1 定義形式

    ----------------------------------------
    // src/content/sprites/bullets.ts
    export const PELLET: SpriteDef = {
      w: 6, h: 6,
      map: { K: 'R0', M: 'R2', P: 'R3', W: 'N8' },
      frames: [[
        '.KKKK.',
        'KMPPMK',
        'KPWWPK',
        'KPWWPK',
        'KMPPMK',
        '.KKKK.',
      ], [
        '.KKKK.',
        'KPMMPK',
        'KMWWMK',
        'KMWWMK',
        'KPMMPK',
        '.KKKK.',
      ]],
      frameTime: 4,
    };
    ----------------------------------------

・. は透明。それ以外の1文字を、map でパレットのキーに対応させる。
・起動時にすべてのスプライトをラスタライズし、テクスチャアトラス（2048×2048のcanvasを1〜2枚）に詰め込む（シェルフ法でパッキング）。
・自動生成する派生:
  ・flash: 白一色のシルエット（ヒットフラッシュ用）
  ・glow: 外側1pxをアイテムの色で縁取ったもの（キャリア用）
  ・flipY: 上下反転（天井版）
  ・rot[n]: 16または32方向の回転済みフレーム（後述）
  ・shards: 4×4pxの断片に切り分けたもの（破片パーティクル用）
・回転: 実行時の回転描画はしない（ピクセルが崩れるため）。必要なスプライトは起動時に「8倍に拡大（nearest）→ 回転 → 各8×8ブロックの最頻色で縮小」する簡易RotSpriteで、事前に回転させておく。大型ボスの部位の回転だけは、実行時の rotate を許可する（imageSmoothingEnabled = false）。

◆ 3.2 手続き描画ユーティリティ（core/render/pixel.ts）

大きなスプライト（ボス、背景、タイル）は、ピクセル単位の描画プリミティブを使うコードで生成する。

| 関数 | 内容 |
|---|---|
| rect / fillRect | 矩形 |
| line | ブレゼンハムの直線 |
| circle / disc | 中点円アルゴリズム |
| poly | スキャンラインによる多角形の塗りつぶし |
| dither(pattern, colorA, colorB, level) | 4×4 Bayerディザ |
| shadeByNormal(mask, lightDir, ramp) | 形状マスクから法線を推定し、色ランプで陰影を付ける（球体、円柱などの立体感） |
| outline(mask, color, selective) | 輪郭の付与 |
| noise2D(seed) | 値ノイズ、fBm（背景や質感用） |

・生成結果はキャッシュし、毎フレーム再生成しない。

◆ 4.1 自機 KESTREL（30×14）

・シルエット: 機首から一本の長い槍状の砲身（ランス）が前方へ突き出し、機体は後退翼のデルタ形。上に小さな垂直尾翼、下に主翼の端が見える。機首を前方へ二股に伸ばした形は採用しない（既存作品の自機を連想させるため）。
・配色: ボディ N7/N8（明部）、N5/N4（陰）、輪郭 N1、機体側面にシアンのライン C3、キャノピー C4/C5、エンジンの開口部 O5/O6。
・フレーム: ニュートラル、上傾き1/2、下傾き1/2（上下に傾くと、主翼の見え方と、キャノピーの反射位置が変わる）。
・エンジン炎: 手続き描画。外側 O4 → O5 → 芯 O6/N8 の3層の三角形。長さは速度Lvで変わり（03 §3.2）、2fごとにランダムな揺らぎ（±1px、rngFx）を加える。速度Lv3以上では、火の粉のパーティクルを出す。
・無敵中: 4fごとに表示・非表示を切り替える（フラッシュ軽減モードでは、点滅させず半透明50%にする）。
・当たり判定の表示（オプション）: コクピットの位置に、白い点（r=2）とマゼンタの輪（r=3）を常に表示する。

◆ 4.2 ドローン WISP（12×12、6フレーム）

◆ 4.6 ボス

・ボスは「パーツ」のスプライトを組み合わせて描く。パーツごとに通常、ヒットフラッシュ、残骸の3状態を用意する。
・最大サイズ: 画面の高さの80%（216px）以内。全長が画面幅を超えるもの（LEVIATHANなど）は、節に分割する。
・生き物らしさの演出: 待機中も呼吸のように±1pxでゆっくり動かす。発光部の明滅、排熱の煙、関節の小さな動きを加える。
・各ボスのデザインの要点は 06 の説明に従う。参考にするモチーフ: WARDEN = 細長い空母と側面の格納庫、GOLEM = 結晶の人型、MATRIARCH = 花のような繭と眼、LEVIATHAN = 機械の鯨と雷、ANVIL = 油圧プレスと炉、CHOIR = 光輪 → 天使像 → 小さな核。

◆ 5.1 背景レイヤーの種類

| 種類 | 内容 |

◆ 5.2 地形タイル

・デカール: リベット、配管、点滅灯、結晶、血管状の発光などを、固定シードで配置する（ベイク時）。点滅灯は描画時にアニメーションさせる。
・テーマ別の質感:

| ST | 質感 |
|---|---|
| 1 | 銀灰色の装甲板、パネルの継ぎ目、シアンの航行灯 |
| 2 | 黒紫の岩 + 半透明の結晶（反射タイルには、内部を流れる光の筋のアニメーション） |
| 3 | 丸みを帯びた肉壁、血管状のシアンの発光、骨色の突起 |
| 4 | 古代の浮遊都市の石材（灰青と苔） |
| 5 | 鋼板、警告ストライプ（黄と黒）、コンベアのローラー（アニメーション） |
| 6 | 白い石材と金の象嵌、共鳴する壁は半透明の水晶 |

■ 9. カメラの演出
------------------------------------------------------------------------

◆ 9.1 画面の揺れ（trauma方式）

・trauma（0〜1）をイベントで加算する。揺れの量 = trauma²。最大オフセット6px（整数に丸める）。回転はしない。
・減衰: 毎秒1.5。
・加算量: small爆発0、medium +0.15、large +0.35、パーツ破壊 +0.35、ボス撃破 1.0、自機の撃墜 +0.5、プレス +0.1。
・揺れはレイヤー0〜14に適用し、HUDとUIには適用しない。
・オプション: OFF / HALF（×0.5） / FULL。

◆ 9.2 ヒットストップとスロー

| イベント | 効果 |
|---|---|
| 自機の撃墜 | 6fの停止 |
| ボスのパーツ破壊 | 4fの停止 |
| ボスの撃破 | 8fの停止 → 60fのスロー（3fに1回だけ更新する） |
| ST6 | ヒットストップは使わない（ビート同期を保つため。フラッシュで代用する） |

◆ 9.3 フラッシュ

・画面全体の単色フラッシュ（白または指定した色）。alphaの開始値と減衰フレーム数を指定する。
・フラッシュ軽減モード: alphaの上限を0.2にし、色を暗くする。3Hzより速い点滅（MINEの警告など）は、点滅させずに一定の発光にする。

■ 10. ロゴとフォント
------------------------------------------------------------------------

・ロゴ「AETHER LANCE」: 幅のある斜体のサンセリフを、ドットで描く（高さ32px、ゲーム解像度で）。文字の色は白からシアンへのグラデーションで、金属的な帯を入れる。タイトル画面では、一本の光の槍が左から右へ文字を貫き（40f）、通った文字が順に光る演出を付ける。下に「エーテルランス」をDotGothic16で添える。
・ビットマップフォント:
  ・font8: 8×8、ASCII 0x20〜0x7E。HUD、メニュー、大きな文字（×2、×3）用。
  ・font5: 4×6、数字と一部の記号。スコアのポップアップ用。
  ・どちらもピクセル文字列でコードに定義する（§3.1と同じ形式）。
・日本語: UIオーバーレイcanvasに DotGothic16 で描く。サイズは実ピクセルで16の整数倍にして、くっきり表示する。フォントを読み込めなかったときは、"Hiragino Kaku Gothic ProN", "Noto Sans JP", sans-serif にフォールバックする。

========================================================================
08. サウンド仕様
========================================================================

■ 1. 方針
------------------------------------------------------------------------

・音声ファイルは1つも使わない。BGMとSEはすべて、WebAudioの自作シンセでリアルタイムに合成するか、起動時に事前レンダリングする。
・目標の音色: PSG（矩形波、三角波、ノイズ）の明快さと、FM音源の厚みを併せ持つ「拡張チップチューン」。リバーブとディレイで空間を作る。
・BGMはメロディを重視し、各ステージの曲を一度聴いたら口ずさめるようにする。ボス曲は緊張感を重視する。
・SEはBGMを邪魔しない。特に、絶えず鳴り続ける自機のショット音は、小さく短くする。

■ 2. オーディオグラフ
------------------------------------------------------------------------

    ----------------------------------------
    [各ボイス] → [チャンネルGain(+Pan)] → [BGMバス 0.55] ─┐
                                       → [SFXバス 0.80] ─┼→ [マスターGain 0.8] → [DynamicsCompressor] → destination
                                       → [UIバス  0.60] ─┘
                ↘ [リバーブ送り] → ConvolverNode（生成したインパルス）→ マスター
                ↘ [ディレイ送り] → DelayNode + フィードバック + LPF → マスター
    ----------------------------------------

| ノード | 設定 |
|---|---|
| Compressor | threshold −14dB、knee 12、ratio 4、attack 3ms、release 150ms |
| Reverb | ステレオのホワイトノイズに指数減衰（1.8秒）を掛けたインパルスを起動時に生成。プリディレイ20ms。送り量: BGMのリードとパッド 0.18、大爆発 0.25 |
| Delay | 付点8分音符（BPMに同期）、フィードバック0.3、ウェット0.15、LPF 3kHz。リード専用 |
| 音量オプション | マスター、BGM、SE を0〜10の11段階。カーブは gain = (v/10)^2 |

・AudioContext はBootシーンの最初のユーザー操作で生成し、resume() する（iOSのため、同じイベントハンドラ内で無音のバッファを1回再生する）。
・iOSでは、マナースイッチがONだとWebAudioが鳴らない。初回起動時のBoot画面に「音が出ない場合は、マナースイッチをオフにしてください」と小さく表示する。

■ 4. シーケンサーとMML
------------------------------------------------------------------------

◆ 4.1 MMLの文法（core/audio/mml.ts）

| コマンド | 意味 |
|---|---|
| t<n> | テンポ（BPM） |
| o<n> / < / > | オクターブの指定（0〜8） / 1つ下げる / 1つ上げる |
| l<n> | 既定の音長（1, 2, 4, 8, 16, 32。付点 . も可） |
| c d e f g a b | 音符。+ または # でシャープ、- でフラット。直後に音長（例: c8.） |
| r | 休符 |
| & / ^ | タイ。c4&c16 は同じ音を伸ばす。^ は直前の音（和音・休符を含む）を音名なしで伸ばす（{ceg}2^8、r4^16） |
| v<0-15> | 音量 |
| @<名前> | 楽器（パッチID） |
| q<1-8> | ゲートタイム（音長に対する発音の割合 n/8） |
| p<-64..64> | パン |
| k<n> | トランスポーズ（半音） |
| [ ... ]<n> | n回の繰り返し。/ は最終回で抜ける位置（[A/B]3 = A B A B A） |
| { ... } | 和音（括弧内の音を同時に鳴らす。音長は閉じ括弧の直後に書く: {ceg}4） |
| ｜ | 小節線（読みやすさのためだけの記号で、解析では無視する） |
| L | ループの開始位置（曲の最後まで来たら、ここへ戻る） |
| ; | 行コメント |

・分解能: 全音符 = 192ティック（4分音符 = 48ティック）。
・拍子: 曲の定義に meter（1小節のティック数。既定は192 = 4/4。7/8なら168）を書ける。ループ長が小節の整数倍になっているかを、ユニットテストで検証する。
・ドラムのトラック（@drums）では、音名をドラムキットに割り当てる: c = kick、d = snare、e = tom、f+ = hat_c、a+ = hat_o、b = crash。
・1曲あたり最大8トラック。トラック名は lead, lead2, arp, bass, pad, drums, fx, drive。

◆ 4.2 曲の定義

    ----------------------------------------
    export const st1: Song = {
      id: 'st1', title: 'Breaking Orbit', bpm: 150,
      tracks: { lead: '...', bass: '...', drums: '...', drive: '...' },
      driveTracks: ['drive'],          // ランスドライブ中だけ鳴らすトラック
      noteEventTracks: [],             // ゲームへ音符イベントを送るトラック（ST6最終ボス）
    };
    ----------------------------------------

◆ 4.3 スケジューリング

・先読み方式: 25msごとのタイマーで、現在時刻から100ms先までの音符を AudioContext.currentTime 基準でスケジュールする。
・ボイスは音符ごとに OscillatorNode と GainNode を生成し、エンベロープは setValueAtTime / linearRampToValueAtTime / setTargetAtTime で書く。BGMの同時発音数は最大24（超えたら、最も古いリリース中のボイスを止める）。
・曲の切り替え: クロスフェード（既定0.5秒）、即時の切り替え、フェードアウトのみ、の3種類。
・タブの非表示とポーズ: 曲の位置を保存して停止し、再開したら同じ位置から鳴らす。

■ 5. 適応的な音楽
------------------------------------------------------------------------

| 状況 | 処理 |
|---|---|
| ランスドライブ | 曲の drive トラック（追加の打楽器とハーモニー）を1拍かけてフェードインする。終了時に1拍かけてフェードアウトする |
| ポーズ | BGMにLPF（600Hz）を0.2秒かけて掛け、−6dB |
| 自機の撃墜 | BGMを60fのあいだ −6dB |
| WARNING | 道中の曲を1.5秒でフェードアウト → 警告のサイレン（warning）→ ボス曲 |
| ボスの撃破 | ボス曲を即座に停止 → 爆発音 → jingle_clear |
| ST6 の「静寂」区間 | 4小節かけてフェードアウトし、heartbeat のみにする |

■ 6. ビート同期（ST6）［MUST］
------------------------------------------------------------------------

・ST6の曲はBPM 150（1拍 = ちょうど24f）。
・主クロックはゲームのフレーム。 ゲームは曲の開始フレームを記録し、beat = floor((frame − startFrame) / 24) で拍を求める。敵の発射はこの拍で決める（決定的）。
・音符イベント: CANTORの旋律弾のために、ゲーム側でも同じMMLを同じパーサで解析し、ティック → フレーム（2ティック = 1f）に変換した音符のリストを持つ。オーディオのクロックには依存しない。
・音声側の追従: シーケンサーは「曲のフレーム → AudioContextの時刻」のアンカーを持つ。ゲームのフレームが処理落ちのスキップで遅れたら、毎秒の確認でアンカーを補正する（1回の補正は最大20ms）。両者のずれは30ms以内に保つ。
・ST6ではヒットストップとスローを使わない（→07 §9.2）。

■ 7. SE
------------------------------------------------------------------------

◆ 7.1 再生の規則

・優先度（1〜5）と同時発音数の上限を、SEごとに持つ。SE全体の同時発音数は16。上限を超えたら、優先度の低いものから止める。
・同じSEの最小間隔: 既定2f（ショット音は4f、ヒット音は3f）。同じフレームの重複は1回にまとめる。
・パン: pan = (x − 240) / 240 × 0.6。
・起動時に OfflineAudioContext で、全SEを AudioBuffer に事前レンダリングする［SHOULD］。再生は AudioBufferSourceNode で行い、ピッチを ±3% ランダムに揺らす（rngFx。連続音の機械っぽさを消すため）。長さが可変のSE（laser_charge など）は、実行時に合成する。

■ 2. UIの共通規則
------------------------------------------------------------------------

・操作: すべてのメニューは、キーボード（上下・決定・キャンセル）、ゲームパッド、マウス（ホバーで選択、クリックで決定）、タッチ（タップで選択と決定）のどれでも操作できる。
・カーソル: 選択中の項目の左に、小さなケストレルのアイコン（8×6）を表示し、左右に2px揺らす。項目の文字は白（N8）、それ以外は灰色（N5）。選択が移ったら menu_move。
・遷移: 黒フェード20f。決定したら menu_confirm、戻るときは menu_cancel。
・キーリピート: 押し続けると、24f後から6fごとにリピートする。
・確認ダイアログ: 破壊的な操作（記録の消去、ゲームの中断）は「はい / いいえ」の確認を出す。既定の選択は「いいえ」。
・文字: 英語の見出しは font8（ゲーム解像度）、日本語の説明文はUIオーバーレイ（DotGothic16）。すべての文字列は i18n のキーで参照する（→§9）。
・安全領域: スマートフォンのノッチやホームバーを避けるため、env(safe-area-inset-*) の分だけUIを内側に寄せる。

◆ 3.8 Pause

・ゲーム画面を暗くし（alpha 0.6）、中央にメニューを出す: RESUME / OPTIONS（AUDIO、VIDEO、ACCESSIBILITYのみ）/ CONTROLS（操作方法の一覧を表示）/ RETRY（PRACTICEのみ）/ QUIT TO TITLE（確認あり）。
・ポーズ中は、現在の装備（武器、Lv、サブ、ドローン、陣形、速度）と、ステージの進捗バーを表示する。
・再開したら、30fの「READY」表示のあと、ゲームが動き出す（入力を再び受け付けるまでの猶予）。

◆ 3.9 StageClear

・「STAGE CLEAR」の文字が左右から滑り込む（20f）。
・ボーナスを1行ずつ表示する（30f間隔）: STAGE CLEAR / NO MISS / BOSS TIME / ITEMS / （2周目なら ×1.5）/ TOTAL。各行の数値は tally の音とともにカウントアップする。
・決定ボタンで集計を早送りできる。最後に「NEXT STAGE ▶」を表示し、フェードして次のステージの紹介へ。

◆ 3.10 GameOver

・「GAME OVER」の文字が1文字ずつ上から落ちてくる。
・コンティニューできる場合: 「CONTINUE? 10」のカウントダウン（60fごとに1減り、countdown が鳴る）。決定ボタンでコンティニューする。キャンセルボタンで1秒ずつ早送りする。
・コンティニューできない場合、またはカウントが0になった場合: ランキング入りしていればNameEntryへ、していなければTitleへ。

◆ 3.11 NameEntry

・3文字の名前を入力する。使える文字: A〜Z、0〜9、. - ! ? ★ ♥、空白、END。
・操作: 上下で文字を切り替え、決定で次の文字へ、キャンセルで1文字戻る。キーボードなら直接タイプしてもよい。タッチは文字のグリッドをタップする。
・制限時間30秒（残り時間を表示する）。時間切れになったら、その時点の文字で確定する。
・前回入力した名前を初期値にする。

◆ 3.12 Ranking

・タブ: EASY / NORMAL / HARD / ORDEAL / BOSS RUSH。左右で切り替える。
・上位10件: 順位、名前、スコア（BOSS RUSHはタイム）、到達（例: 2-4、ALL、ALL 2）、日付、フラグ（C×n、CP、ASSIST）、主に使った武器のアイコン。
・今回ランクインした行を点滅させる。

◆ 3.13 Ending / Credits

・エンディング（→01 §3.3）は、最大90秒の演出。決定ボタンの長押し（1秒）でスキップできる（押している間、ゲージを表示する）。
・クレジット（src/content/credits.ts で編集できる）: 
  ・GAME DESIGN / PROGRAM / GRAPHICS / MUSIC / SOUND — <作者名>（既定値は YOU。作者が自分の名前に書き換える）
  ・DEVELOPED WITH Claude Code
  ・FONT: DotGothic16 (SIL OFL 1.1)
  ・SPECIAL THANKS: AND YOU, PILOT.
・最後にプレイの統計（スコア、プレイ時間、ミス数、撃破数、命中率）を表示する。

      stats: { playTimeSec: number; kills: number; deaths: number; credits: number; weaponUse: Record<WeaponType, number>; };
      lastName: string;
      achievements?: string[];
      replays?: ReplayMeta[];                                   // [SHOULD] 各難易度のベストのみ
    }
    interface RankEntry { name: string; score: number; reach: string; date: string; flags: string[]; weapon: WeaponType; }
    ----------------------------------------

・キー: aetherlance.save.v1。リプレイの本体は aetherlance.replay.<id> に別に保存する（入力ログをRLE圧縮してbase64で。1プレイあたり約30KB以下）。
・読み込みのとき、version を見て順番にマイグレーションする。壊れたデータ（JSONの解析失敗、型の不一致）は、該当する部分だけ既定値に戻す（全消去しない）。
・保存のタイミング: 設定の変更時、ステージクリア時、ゲームオーバー時、ランキングの登録時。ゲーム中には保存しない（ヒッチを避けるため）。

■ 9. 多言語
------------------------------------------------------------------------

・src/i18n/ja.ts と src/i18n/en.ts に、同じキーの集合を持たせる（キーの欠けは単体テストで検出する）。
・固有名詞（ステージ名、ボス名、武器名）は、英語の大文字を両言語で共通に使う。日本語版では、ステージの副題（「軌道環」など）と説明文だけを日本語にする。
・テキストは文字数が変わっても崩れないように、オーバーレイでの折り返しと、はみ出したときの縮小に対応する。

■ 3. テスト計画
------------------------------------------------------------------------

◆ 3.1 単体テスト（vitest）

| 対象 | テストの内容 |
|---|---|
| dmath | dsin / dcos / datan2 の誤差が 1e-6 以下（1万点）。同じ入力に対して、常に同じビット列を返す |
| rng | 同じシードから同じ数列が出る。分布に偏りがない（簡易のカイ二乗） |
| 衝突 | 円と円、円とAABB、カプセル、地形マスクのサンプリング、斜面 |
| 地形のベイク | 各セグメントの型が、期待どおりのタイル列になる |
| タイムライン | イベントがフレームの順に実行される。waitUntil で止まる |
| 武器 | balance.ts の表どおりの弾数、角度、間隔、威力 |
| スコア | 至近距離、編隊ボーナス、ドライブの倍率、エクステンドの閾値、コンティニュー時の下1桁 |
| ランク | 計算式（03 §8）と、上限と下限 |
| MML | 音長、付点、タイ、オクターブ、繰り返し、ループの位置、ティック数の合計 |
| セーブ | マイグレーション、壊れたデータの部分的な復旧 |
| i18n | ja と en のキーの集合が一致する |
| ステージデータ | すべてのステージで validateStage が通る（未定義の敵ID、範囲外の座標、アイテムの合計数） |

◆ 3.2 シミュレーションテスト（Node上で描画なし）

・決定性: ワールドを描画なしで動かし、収録した入力ログ（各ステージ1本ずつ）を2回再生する。終了時の状態のハッシュが一致すること。ゴールデンハッシュをリポジトリに保存し、意図的に変えたときだけ更新する。
・フェアネスの自動チェック（開発ビルドの assert）:
  ・敵弾が自機から40px以内に生成されていない。
  ・予告の長さが、難易度ごとの最小値以上である。
  ・敵が画面に入ってから20f以内に発射していない。
  ・復活シーケンス中に敵弾が生成されていない。
・ボットによる生存テスト［SHOULD］: 簡単な回避ボット（危険な弾を、ポテンシャル場で避ける）を無敵にして全ステージを走らせ、「回避できない状況」（自機の周囲の全方向が塞がれたフレーム）を検出して記録する。

| リスク | 対策 |
|---|---|

    ----------------------------------------
    // FNV-1a 32bit。ワールドの主要な値を、決まった順序で投入する
    function worldHash(w: World): string {
      let h = 0x811c9dc5;
      const mix = (v: number) => { h ^= (v * 1000) | 0; h = Math.imul(h, 0x01000193) >>> 0; };
      mix(w.frame); mix(w.score); mix(w.player.x); mix(w.player.y); mix(w.player.lv); mix(w.rank);
      for (const e of w.enemies.activeInOrder()) { mix(e.def.idHash); mix(e.x); mix(e.y); mix(e.hp); }
      for (const b of w.bullets.activeInOrder()) { mix(b.x); mix(b.y); }
      mix(w.rngGame.state);
      return h.toString(16).padStart(8, '0');
    }

■ 2. 追加した機能
------------------------------------------------------------------------

・リプレイ: ARCADE と BOSS RUSH のプレイはすべて入力を記録する。各ランキングの1位はリプレイとして保存し、ランキング画面で Z キーを押すと再生できる。保存形式は「(ビット列, 連続数) のRLE → 可変長整数 → base64」。タッチとアナログの値は記録できる精度に丸めてからゲームに渡すので、再生は完全に一致する。ステージごとのショット方式と、ゲーム画面内の選択（集計の早送り、コンティニュー）も入力として記録する。
・フォントの同梱: DotGothic16 を、画面に出す文字だけのサブセット（約23KB）にして同梱した。どのビルドもネットワークに一切接続しない。文字を増やしたら node scripts/subset-font.mjs で作り直す（足りない文字はユニットテストで検出する）。
・Android アプリ（APK）: aether-lance/android/。全画面・横向きの WebView で単一HTML版を動かす。ページは APK 内の資産から https://appassets.androidplatform.net/ として配信するので、localStorage・WebAudio・WebGL2 がブラウザと同じに動く。通信の権限は持たない。戻るボタンは、ゲーム中はポーズ、メニューでは戻る、タイトル画面ではアプリの終了。すべての版を同じ鍵で署名するので、上書きインストールでセーブデータを引き継げる。
・HD 版（別バージョン）: ゲームの中身は同じで、絵を現代的な高品位グラフィックに描き直した版。キャラクターは同じ設計図から3倍の解像度で連続した陰影・光沢・リムライト・滑らかな輪郭で作り直し、地形は滑らかな輪郭とステージごとの新しい質感（金属パネル、岩と結晶、有機体、石材、ハザード塗装、大理石と金）、背景は滑らかなグラデーション、エフェクトは光る弾・ビーム・柔らかい爆発、文字はベクターフォント（Rajdhani）。ビルド時の切り替え（npm run build:single:hd）で作り、Android では別アプリ（com.aetherlance.game.hd）として通常版と共存できる。
・PV（プロモーション映像）: node scripts/make-pv.mjs で、文字のない40秒の映像（1080p・60fps、ゲーム内のBGMと効果音つき）を書き出す。ゲームを1フレームずつ進めて撮影し、音はオフラインのオーディオコンテキストで映像の時間に合わせて合成する。

| 復活位置（ステージ5） | 縦穴では決まった復活位置 (60, 135) が壁の中で、無敵時間が切れた瞬間にまた死に、残機がなくなるまで5秒ごとに繰り返していた。入場と無敵時間のあいだ地形にかからない、いちばん近い場所から復活するようにした（コンティニュー後も同じ） |

| ステージ1ボスのハッチ | 前半の目標のハッチが装甲の後ろにあり、正面からの弾が届かず、50秒の時間切れを待つしかなかった（ボス戦が95〜120秒かかっていた）。ハッチの当たり判定を船首まで伸ばした。後半に撃つ核の前の装甲のすき間も、設計（26ピクセル）より狭い18ピクセルになっていたので、設計どおりにした |
| SEEKER とステージ2ボス | 追尾ミサイルが敵の中心を狙うため、ステージ2ボスでは「撃たれると反撃レーザーを撃つ胸のクリスタル」に当たり続けていた。ダメージを受ける部位のうち近いものを狙うようにした |
| 安全地帯の表示（ステージ5ボス） | 上下の壁が閉じる前に、残るすき間を緑の帯で示す作りだったが、帯の描画が色の指定を無視してオレンジで描いていたため、同じステージのプレスの「危険」の予告と見分けがつかなかった。帯は指定の色で描くようにした（オレンジ＝危険、それ以外の色＝安全） |
| ボスの耐久 | 一律3.6倍だったダメージ倍率をステージごとに変えた（BOSS_DMG）。そのステージでの普通の装備で中ボスは約10〜20秒、ボスは約40〜80秒。ミスで装備を失った中盤の装備（Lv3、ドローン2機、サブ武器なし）でも、すべて制限時間内に倒せることをユニットテストで確認している |
| SEEKER のボスへの威力 | 弱点を狙うようにした結果、ボス戦では SEEKER が強すぎた（ステージ2のボスが11〜19秒で、ステージ1のボスより短かった）ため、ボスと中ボスへのダメージを半分にした |
| 実機でのコマ落ち | 通常版は 256×256 の地形の区画を、画面に入るフレームでまとめて描いていた（1区画4〜35ミリ秒、1フレームに2区画まで）。さらに描いた画像を初めて画面に貼るときにも20〜40ミリ秒かかっていた。区画を画面の先から1フレーム2.5ミリ秒ずつ描き、できた画像は別スレッドで GPU 向けに変換するようにした（HD 版も同じ）。地形が原因の12ミリ秒を超えるフレームは、1ステージあたり8〜25回から0〜1回になった |
| バージョン | v1.1.1（v1.1.0 のリプレイは再生しない） |

■ 4. 実機での自動テスト
------------------------------------------------------------------------

・自動テストモード: URL に ?autotest=<分> を付けると、先読み型の自動操縦（無敵ではない）が各ステージを「そのステージに普通に着いたときの装備」（03 §5.7）で順に遊ぶ。難易度（diff=normal,hard）と武器（PULSE / FAN / RAY）を入れ替え、1回の挑戦につき3回までコンティニューする。死亡（原因つき）、中ボスとボスの結果と時間、クリア、30秒ごとの FPS を、コンソールに ALTEST {json} の1行ずつで出す。終わると画面に集計表を出す。
・先読み型の自動操縦（src/game/planner.ts）: 毎フレーム、8方向＋停止の9通りを6フレーム、続けてもう一度9通りを最大26フレーム先まで試し、スクロールする地形（カメラの経路は正確に分かる）、弾、敵の体、レーザーなどの危険（予告中で撃たれる直前のものを含む）との接触を予測して、いちばん安全で、かつ敵を狙える経路を選ぶ。慎重な普通のプレイヤー程度の腕にして、死亡がゲームの側の問題を示すようにした。アトラクトデモと無敵のテストは従来の自動操縦のまま。
・Android アプリ: 起動時のインテントの query を開く URL に付け、ALTEST の行とページのエラーを logcat（タグ AetherLance）に出す。
・実機テストのスクリプト（scripts/device-test.py）: スマートフォンをつないだパソコンで実行する。APK のインストール、テストの開始、logcat の読み取り、端末温度の記録、アプリが落ちたときの再起動、5分ごとの画面の撮影を行う。ローカル LLM（Ollama、または OpenAI 互換のサーバー）が動いていれば、画像を読めるモデルに画面を確認させ、最後に集計と自動で見つけた問題点をもとにバランスの所見をまとめさせて、report.md に出す。

■ 5. 実装していないもの（［COULD］）
------------------------------------------------------------------------

・SCORE ATTACK モード（03 §12）。
・統計画面と実績（03 §13）。通算の統計はセーブデータに記録し、プレイごとの記録（FLIGHT RECORD）はエンディングに表示する。
・「回避できない弾の配置」を自動で探すボット（10 §3、［SHOULD］）は一部のみ。自動操縦で全ステージをクリアし、全ボスを倒せることは確認している。

■ 6. テスト
------------------------------------------------------------------------

・ユニットテスト（Vitest、72件）: MMLと曲の小節の整合、全ステージの自動クリア、決定性、全ボス・中ボスの撃破（中盤の装備で PULSE / FAN / RAY のそれぞれ）、ステージ5の縦穴で壁の中に復活しないこと、リプレイの符号化と再生の一致、同梱フォントの文字の網羅。
・E2Eテスト（Playwright、9件）: 起動、プレイと得点、ポーズ、タッチ操作（iPhone 12）、実プレイとリプレイの一致、1位のリプレイの保存と再生、単一HTML版（file://）、Android アプリと同じ条件（専用のオリジン・オフライン・戻るボタン・セーブの保持）、HD 版の起動とプレイ。
