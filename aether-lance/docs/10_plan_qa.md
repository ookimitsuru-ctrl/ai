# 10. 開発計画・品質保証

## 1. マイルストーン

各マイルストーンの完了時には、「受け入れ基準」を**すべて**満たし、そのうえでコミットしてpushする。各マイルストーンの終わりに、遊べるビルド（単一HTML）を作る。

### M0 基盤

| 作業 | 内容 |
|---|---|
| プロジェクト | Vite + TS の雛形、eslint、prettier、vitest、playwright、`build:single` |
| コア | 固定タイムステップのループ、シーンスタック、入力（キーボード、パッド、タッチ）とアクション写像、決定的な数学関数と乱数、プール、コルーチン |
| 描画 | ゲームcanvas、スプライト定義からアトラスの生成、ビットマップフォント、プレゼンテーション（WebGL2とフォールバック）、UIオーバーレイ |
| 音 | AudioContextの有効化、SEの事前レンダリング、テスト用のSE数個 |
| デバッグ | デバッグオーバーレイの雛形（FPS、エンティティ数） |

**受け入れ基準:**
- テスト用のシーンで、自機がキーボード、パッド、タッチのそれぞれで動き、PULSEを撃てる。基準機で60fpsを保つ。
- `dmath` と `rng` の単体テストが通る。`npm run lint` がエラーなしで通る。
- 単一HTMLのビルドを、ダブルクリック（`file://`）で開いて動かせる。

## 2. 完了の定義（全タスク共通）

1. 型エラーとlintエラーがない。
2. 関係する単体テストを追加し、すべてのテストが通る。
3. コンソールにエラーも警告も出ない。
4. ゲーム中のヒープ確保ゼロの規則（02 §5.1）を守っている（Chrome DevToolsのメモリのタイムラインで確認）。
5. 数値は `balance.ts` かコンテンツの定義にある。変えたら本書も更新した。

## 3. テスト計画

### 3.1 単体テスト（vitest）

| 対象 | テストの内容 |
|---|---|
| `dmath` | `dsin / dcos / datan2` の誤差が 1e-6 以下（1万点）。同じ入力に対して、常に同じビット列を返す |
| `rng` | 同じシードから同じ数列が出る。分布に偏りがない（簡易のカイ二乗） |
| 衝突 | 円と円、円とAABB、カプセル、地形マスクのサンプリング、斜面 |
| 地形のベイク | 各セグメントの型が、期待どおりのタイル列になる |
| タイムライン | イベントがフレームの順に実行される。`waitUntil` で止まる |
| 武器 | `balance.ts` の表どおりの弾数、角度、間隔、威力 |
| スコア | 至近距離、編隊ボーナス、ドライブの倍率、エクステンドの閾値、コンティニュー時の下1桁 |
| ランク | 計算式（03 §8）と、上限と下限 |
| MML | 音長、付点、タイ、オクターブ、繰り返し、ループの位置、ティック数の合計 |
| セーブ | マイグレーション、壊れたデータの部分的な復旧 |
| i18n | ja と en のキーの集合が一致する |
| ステージデータ | すべてのステージで `validateStage` が通る（未定義の敵ID、範囲外の座標、アイテムの合計数） |

### 3.2 シミュレーションテスト（Node上で描画なし）

- **決定性:** ワールドを描画なしで動かし、収録した入力ログ（各ステージ1本ずつ）を2回再生する。終了時の状態のハッシュが一致すること。ゴールデンハッシュをリポジトリに保存し、意図的に変えたときだけ更新する。
- **フェアネスの自動チェック（開発ビルドの assert）:**
  - 敵弾が自機から40px以内に生成されていない。
  - 予告の長さが、難易度ごとの最小値以上である。
  - 敵が画面に入ってから20f以内に発射していない。
  - 復活シーケンス中に敵弾が生成されていない。
- **ボットによる生存テスト［SHOULD］:** 簡単な回避ボット（危険な弾を、ポテンシャル場で避ける）を無敵にして全ステージを走らせ、「回避できない状況」（自機の周囲の全方向が塞がれたフレーム）を検出して記録する。

### 3.3 E2Eテスト（Playwright）

| シナリオ | 確認すること |
|---|---|
| 起動 | ページを開いてクリックすると、タイトルが表示される（canvasのピクセルが黒以外）。コンソールにエラーがない |
| ゲーム開始 | キーボードでARCADE → NORMAL → ステージ1を開始し、Zを5秒押し続ける。スコアが0より大きくなる |
| ポーズ | Escでポーズし、再開できる |
| モバイル | iPhone 12のエミュレーション（タッチ）でドラッグすると、自機が動く |
| 単一HTML | `dist-single/aether-lance.html` を `file://` で開き、起動のシナリオが通る |
| 負荷 | デバッグのストレスシーン（敵弾600、パーティクル2000）で、平均フレーム時間が10ms未満（CIでの参考値） |

### 3.4 手動テスト

- 実機: Windows（Chrome）、macOS（Safari）、iPhone（Safari、ホーム画面に追加した状態も）、Android（Chrome）、Xbox/PlayStation系のコントローラー。
- 各マイルストーンで、§5のチェックリストを実施する。

## 4. バランス調整

### 4.1 目標

| 指標 | 目標 |
|---|---|
| 初めてのプレイヤー（NORMAL） | 1回目でステージ2〜3に到達する |
| STGの経験者（NORMAL） | 5〜10回の挑戦で、ノーコンティニューの1周クリア |
| EASY | 初めてのプレイヤーの多くが、コンティニューを使えばエンディングを見られる |
| HARD | 経験者が20回以上の挑戦でクリアを目指せる |
| ステージの難易度曲線 | ミスの発生率がステージ1 → 6でなめらかに増える。中ボスとボスでミスの40%程度 |
| ボス戦の時間 | 06 §1.7 の目標の±20%以内 |

### 4.2 計測（デバッグビルドのテレメトリ）

- ミスした位置（ステージ、時刻、セクション、原因の敵か弾の種類）、ボス戦の時間、アイテムの取得率、武器の使用率を localStorage に記録し、JSONで書き出せるようにする。
- セクション別のミスのヒートマップを、デバッグ画面に表示する。
- 外部へは一切送信しない。

## 5. QAチェックリスト

### 5.1 気持ちよさのチェック（M1以降、毎回）

- [ ] ショットボタンを押したフレームに弾が出る（録画でコマ送りして確認）
- [ ] すべての命中に、フラッシュ、音、火花がある
- [ ] すべての撃破に、爆発、音、点数がある。大物ほど派手
- [ ] アイテムの取得が目と耳で分かり、何が強くなったかを表示する
- [ ] 自機の動きに慣性がなく、止めたい位置でぴたりと止まる
- [ ] 速度の切り替え、陣形の切り替えが、手応えとして分かる
- [ ] ランスドライブの発動が、作品で一番気持ちいい瞬間になっている
- [ ] ボスの撃破が、ステージの締めくくりとして十分に派手

### 5.2 フェアネスと視認性

- [ ] すべてのステージの、すべての背景の上で、敵弾がはっきり見える（スクリーンショットをグレースケールにしても見える）
- [ ] 危険なギミックにはすべて予告がある（音を消しても分かる）
- [ ] 後方からの敵には警告がある
- [ ] ミスの直後に、理不尽な連続ミスが起きない
- [ ] 当たり判定の表示がONのとき、表示どおりの判定になっている

### 5.3 機能

- [ ] 全ステージを2周クリアできる（EASY〜ORDEAL）
- [ ] CHECKPOINT方式で、各チェックポイントから正しく再開できる
- [ ] PRACTICE、BOSS RUSHが動く。解放条件が正しい
- [ ] コンティニュー、ネームエントリー、ランキングが正しい
- [ ] オプションのすべての項目が、即座に反映され、再起動しても保持される
- [ ] キーコンフィグで重複を作れない。初期化できる
- [ ] ゲームパッドの抜き差しで、クラッシュも操作不能も起きない
- [ ] タブの切り替え、ウィンドウのフォーカス喪失で自動的にポーズする。キーが押しっぱなしにならない
- [ ] localStorageが使えない環境（プライベートモード）でも遊べる

### 5.4 プラットフォーム

- [ ] iPhone Safari: 音が鳴る（マナースイッチOFF時）、タッチ操作、縦持ちと横持ち、ホーム画面からの起動でフルスクリーン、ノッチの回避
- [ ] Android Chrome: タッチ、フルスクリーン、戻るボタンでポーズ、振動
- [ ] PC: 拡大方式すべて、高DPIディスプレイでぼやけない、144Hzのディスプレイでなめらか
- [ ] WebGL2が使えない環境で、フォールバックの描画で遊べる

### 5.5 IP・品質

- [ ] 新しく追加した名称、意匠、旋律が、既存作品の固有要素を模倣していない（01 §5）
- [ ] 外部の素材を使っていない（フォントを除く）
- [ ] すべての文字列が i18n を通っている。英語版と日本語版の両方で、レイアウトが崩れない
- [ ] 誤字脱字がない

## 7. リスクと対策

| リスク | 対策 |
|---|---|
| iOSで音が鳴らない、遅れる | ユーザー操作の中でのアンロック、マナースイッチの案内、SEの事前レンダリング |
| iPhoneでフルスクリーンにできない | PWA（ホーム画面に追加）を案内する。縦持ちのレイアウトも用意する |
| モバイルのGPUが弱い | 自動品質調整、ブルームの縮小、パーティクルの削減、WebGLなしのフォールバック |
| GCによるカクつき | プール、ホットパスでの確保の禁止、DevToolsで確認 |
| 入力の遅延 | 描画前の入力のサンプリング、補間の任意化、`desynchronized: true` のcanvasコンテキスト［COULD］ |
| 日本語フォントの読み込みの遅れ | Bootで読み込みを待つ（最大2秒）。失敗したらシステムフォントへフォールバック |
| 高DPIでのぼやけ | 実ピクセル単位での整数倍の拡大、CSSの `image-rendering: pixelated` |
| 内容の量が多く、品質がばらつく | M1でステージ1を完成品質にし、そこで作ったツール（地形DSL、パターンライブラリ、スクリプトAPI）と品質基準を、以降のステージにそのまま使う |
| 既存作品との類似 | 01 §5 のガイドラインと、各マイルストーンでのチェック |
