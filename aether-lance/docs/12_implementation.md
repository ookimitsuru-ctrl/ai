# 12. 実装メモ: 指示書からの変更点と追加機能

> 本書（00〜11）をもとに実装した v1.0.0 で、指示書と違う作りにした点と、指示書のあとで追加した機能をまとめる。英語版の詳細は `aether-lance/IMPLEMENTATION_NOTES.md`。

## 1. 指示書から意図的に変えた点

| 項目 | 指示書 | 実装 | 理由 |
|---|---|---|---|
| 地形 | 16×16タイル＋マスク（02 §7.3） | 256×256のチャンクに分けた1ピクセル単位の材質ビットマップ（岩・結晶・破壊可能・コンベア左右・交互） | 挙動は同じで、地形の作り込みが簡単になる |
| ビットマップフォント | 8×8（07 §10） | 6×8セルに5×7の字形 | 480×270の画面で読みやすい |
| 敵の当たり判定の前処理 | 一様グリッド（02 §7.2） | 総当たり | 敵の数が少なく、十分に速い |
| デバッグ機能 | 動的import | 本体に同梱（`?debug` のときだけ有効） | 単一HTML版を1ファイルに保つため |
| MML | `\|` が繰り返しの抜け位置 | `\|` は小節線。抜け位置は `/`。`^` のタイ、`{}` の和音、曲ごとの拍子 `meter` を追加 | 08 §4.1 を更新済み |
| ステージ2の分岐 | 画面より高いワールドを縦カメラで追う（02 §6） | 画面の高さの中で上下ルートに分ける | 見通しがよく、地形の作り込みも簡単 |
| アトラクトデモ | 開発者のプレイを録画したリプレイ（09 §3.3） | 自動操縦（無敵）がステージ1を90秒プレイ | バランス調整をしてもデモがずれない |
| 画面の拡大方式の既定値 | INTEGER | INTEGER（タッチ端末では FIT） | スマートフォンの小さい画面を広く使う |
| 消音スイッチの案内 | ブート画面に表示 | iPhone / iPad のときだけ表示 | Android やPCには関係がない |

## 2. 追加した機能

- **リプレイ:** ARCADE と BOSS RUSH のプレイはすべて入力を記録する。各ランキングの1位はリプレイとして保存し、ランキング画面で Z キーを押すと再生できる。保存形式は「(ビット列, 連続数) のRLE → 可変長整数 → base64」。タッチとアナログの値は記録できる精度に丸めてからゲームに渡すので、再生は完全に一致する。ステージごとのショット方式と、ゲーム画面内の選択（集計の早送り、コンティニュー）も入力として記録する。
- **フォントの同梱:** DotGothic16 を、画面に出す文字だけのサブセット（約23KB）にして同梱した。どのビルドもネットワークに一切接続しない。文字を増やしたら `node scripts/subset-font.mjs` で作り直す（足りない文字はユニットテストで検出する）。
- **Android アプリ（APK）:** `aether-lance/android/`。全画面・横向きの WebView で単一HTML版を動かす。ページは APK 内の資産から `https://appassets.androidplatform.net/` として配信するので、localStorage・WebAudio・WebGL2 がブラウザと同じに動く。通信の権限は持たない。戻るボタンは、ゲーム中はポーズ、メニューでは戻る、タイトル画面ではアプリの終了。すべての版を同じ鍵で署名するので、上書きインストールでセーブデータを引き継げる。
- **HD 版（別バージョン）:** ゲームの中身は同じで、絵を現代的な高品位グラフィックに描き直した版。キャラクターは同じ設計図から3倍の解像度で連続した陰影・光沢・リムライト・滑らかな輪郭で作り直し、地形は滑らかな輪郭とステージごとの新しい質感（金属パネル、岩と結晶、有機体、石材、ハザード塗装、大理石と金）、背景は滑らかなグラデーション、エフェクトは光る弾・ビーム・柔らかい爆発、文字はベクターフォント（Rajdhani）。ビルド時の切り替え（`npm run build:single:hd`）で作り、Android では別アプリ（`com.aetherlance.game.hd`）として通常版と共存できる。
- **PV（プロモーション映像）:** `node scripts/make-pv.mjs` で、文字のない40秒の映像（1080p・60fps、ゲーム内のBGMと効果音つき）を書き出す。ゲームを1フレームずつ進めて撮影し、音はオフラインのオーディオコンテキストで映像の時間に合わせて合成する。

## 3. v1.1 の変更（プレイしたうえでの調整）

| 項目 | 内容 |
|---|---|
| 自機のデザイン | KESTREL を Mk.II に描き直した（40×20）。白い装甲に赤いライン、上下に2基の大型プロペラントタンク（手前のタンクと、奥のタンクが船体の上にのぞく）、両翼端の長いレーザー砲、後部の青い2連イオンエンジン。噴射炎も青に変更。当たり判定は変えていない。HUD の残機アイコン、両版のアプリアイコンも新デザインに合わせた |
| 敵の出現テンポ | ステージごとの「つなぎ編隊」（そのステージの小型敵の編隊）を追加。台本の編隊の合間に、画面の敵が5体未満になると右端（縦スクロール区間では上端）の空いている所から出す。台本の出現の直前とボス・中ボスの登場前6秒、ステージ6の静寂区間は出さない。乱数はゲーム用のものを使うので、決定性とリプレイは保たれる。敵がいない時間の最長は、ボス前と演出区間を除いて30〜40秒から約4〜5秒になった |
| ボスの耐久 | 攻撃はそのままで、中ボスとボスへの自機のダメージを3.6倍（FAN はさらに1.8倍）にした。中盤の装備（Lv3、ドローン2機、サブ武器なし）で、どの武器でも全ボス・中ボスを制限時間内に倒せることをユニットテストで確認している |
| 不具合修正 | RAY（レーザー）の軌跡が発射直後に空になり、敵に一切当たっていなかった（画面には白い点だけが飛んでいた）。修正済み |
| バージョン | v1.1.0。バランスが変わったため、v1.0 のリプレイは再生しない |

## 3.1 v1.1.1 の変更（自動テストでの調整）

先読み型の自動操縦で全ステージ × 3武器 × NORMAL / HARD を通しで遊ばせ、ボス戦の時間も測って見つけた問題を直した。

| 項目 | 内容 |
|---|---|
| 復活位置（ステージ5） | 縦穴では決まった復活位置 (60, 135) が壁の中で、無敵時間が切れた瞬間にまた死に、残機がなくなるまで5秒ごとに繰り返していた。入場と無敵時間のあいだ地形にかからない、いちばん近い場所から復活するようにした（コンティニュー後も同じ） |
| プレスの予告（ステージ5） | プレスは地形と一緒に流れるのに、予告の帯は予告を出した時の位置に止まっていたため、実際に落ちる位置が最大で約26ピクセルずれていた。帯がプレスについて動くようにした |
| ステージ1ボスのハッチ | 前半の目標のハッチが装甲の後ろにあり、正面からの弾が届かず、50秒の時間切れを待つしかなかった（ボス戦が95〜120秒かかっていた）。ハッチの当たり判定を船首まで伸ばした |
| SEEKER とステージ2ボス | 追尾ミサイルが敵の中心を狙うため、ステージ2ボスでは「撃たれると反撃レーザーを撃つ胸のクリスタル」に当たり続けていた。ダメージを受ける部位のうち近いものを狙うようにした |
| 安全地帯の表示（ステージ5ボス） | 上下の壁が閉じる前に、残るすき間を緑の帯で示す作りだったが、帯の描画が色の指定を無視してオレンジで描いていたため、同じステージのプレスの「危険」の予告と見分けがつかなかった。帯は指定の色で描くようにした（オレンジ＝危険、それ以外の色＝安全） |
| ボスの耐久 | 一律3.6倍だったダメージ倍率をステージごとに変えた（`BOSS_DMG`）。そのステージでの普通の装備で中ボスは約10〜20秒、ボスは約40〜80秒。ミスで装備を失った中盤の装備（Lv3、ドローン2機、サブ武器なし）でも、すべて制限時間内に倒せることをユニットテストで確認している |
| バージョン | v1.1.1（v1.1.0 のリプレイは再生しない） |

## 4. 実機での自動テスト

- **自動テストモード:** URL に `?autotest=<分>` を付けると、先読み型の自動操縦（無敵ではない）が各ステージを「そのステージに普通に着いたときの装備」（03 §5.7）で順に遊ぶ。難易度（`diff=normal,hard`）と武器（PULSE / FAN / RAY）を入れ替え、1回の挑戦につき3回までコンティニューする。死亡（原因つき）、中ボスとボスの結果と時間、クリア、30秒ごとの FPS を、コンソールに `ALTEST {json}` の1行ずつで出す。終わると画面に集計表を出す。
- **先読み型の自動操縦**（`src/game/planner.ts`）: 毎フレーム、8方向＋停止の9通りを6フレーム、続けてもう一度9通りを最大26フレーム先まで試し、スクロールする地形（カメラの経路は正確に分かる）、弾、敵の体、レーザーなどの危険（予告中で撃たれる直前のものを含む）との接触を予測して、いちばん安全で、かつ敵を狙える経路を選ぶ。慎重な普通のプレイヤー程度の腕にして、死亡がゲームの側の問題を示すようにした。アトラクトデモと無敵のテストは従来の自動操縦のまま。
- **Android アプリ:** 起動時のインテントの `query` を開く URL に付け、`ALTEST` の行とページのエラーを logcat（タグ `AetherLance`）に出す。
- **実機テストのスクリプト**（`scripts/device-test.py`）: スマートフォンをつないだパソコンで実行する。APK のインストール、テストの開始、logcat の読み取り、端末温度の記録、アプリが落ちたときの再起動、5分ごとの画面の撮影を行う。ローカル LLM（Ollama、または OpenAI 互換のサーバー）が動いていれば、画像を読めるモデルに画面を確認させ、最後に集計と自動で見つけた問題点をもとにバランスの所見をまとめさせて、`report.md` に出す。

## 5. 実装していないもの（［COULD］）

- SCORE ATTACK モード（03 §12）。
- 統計画面と実績（03 §13）。通算の統計はセーブデータに記録し、プレイごとの記録（FLIGHT RECORD）はエンディングに表示する。
- 「回避できない弾の配置」を自動で探すボット（10 §3、［SHOULD］）は一部のみ。自動操縦で全ステージをクリアし、全ボスを倒せることは確認している。

## 6. テスト

- ユニットテスト（Vitest、72件）: MMLと曲の小節の整合、全ステージの自動クリア、決定性、全ボス・中ボスの撃破（中盤の装備で PULSE / FAN / RAY のそれぞれ）、ステージ5の縦穴で壁の中に復活しないこと、リプレイの符号化と再生の一致、同梱フォントの文字の網羅。
- E2Eテスト（Playwright、9件）: 起動、プレイと得点、ポーズ、タッチ操作（iPhone 12）、実プレイとリプレイの一致、1位のリプレイの保存と再生、単一HTML版（file://）、Android アプリと同じ条件（専用のオリジン・オフライン・戻るボタン・セーブの保持）、HD 版の起動とプレイ。
