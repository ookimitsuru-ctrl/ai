# AIフォロワーSNS(仮称「ひとりごと」)仕様書 v0.1(概要版)

作成日: 2026-11-10 / ステータス: ドラフト(概要レベル。詳細設計は未着手)

---

## 1. コンセプト

- ユーザーが1人で使う「架空のSNS」。登場するフォロワー・リアクションはすべてAI(LLM)が生成する。
- フォロワーは最初 **0人**。ユーザーがつぶやくたびに、内容に興味を持った **架空の20人** が少しずつフォローしてくる。
- 20人にはそれぞれ **個性(職業・性格・口調・関心領域)** があり、自分の関心が強い話題には食いつき、関心のない話題には反応しない。
- 「何をつぶやくと誰が来るか」を試して、**自分のつぶやきでフォロワーが育っていく手応え** を楽しむ。

### 1.1 ゴール / 非ゴール

| ゴール | 非ゴール(v1ではやらない) |
|---|---|
| つぶやき投稿 → フォロワー増加 → リアクション(いいね・返信)の一連の体験 | 複数ユーザー・実在ユーザーとの交流 |
| 20人の個性が会話から明確に伝わること | 実在の人物・企業・SNSの模倣 |
| 話題によって集まるフォロワーが変わること | 広告・課金・外部SNS連携 |

---

## 2. 用語

| 用語 | 意味 |
|---|---|
| つぶやき | ユーザーの投稿(最大140字想定) |
| ペルソナ | 20人のフォロワーそれぞれのキャラクター定義 |
| 関心トピック | 話題の分類タグ(例: 料理、ランニング、プログラミング) |
| 親和度(affinity) | つぶやき内容とペルソナの関心の一致度(0〜1) |
| 候補プール | まだフォローしていない架空ユーザー(最初は20人全員) |

---

## 3. 主な機能

### 3.1 つぶやき投稿
- テキスト入力(140字)→ 投稿でタイムラインに追加。
- 投稿直後に「話題解析 → フォロー判定 → リアクション生成」が走る(§5)。

### 3.2 フォロワーの増加
- 投稿ごとに、候補プールの各ペルソナについて **フォローするか判定**。
- 1投稿で増える人数は **最大3人**(急に増えすぎない / 小出しにする)。
- 新規フォロワーは「〇〇さんにフォローされました」の通知と、フォローのきっかけになった一言コメントを返す。
- 話題が合わなければ0人の投稿もある(それも楽しみのうち)。

### 3.3 リアクション
- フォロワーは投稿に対して以下を行う:
  - **いいね**: 親和度が中程度以上
  - **返信**: 親和度が高い / 「強い関心トピック」に触れた場合(ほぼ確実に返信)
  - **スルー**: 関心がない場合
- 返信は各ペルソナの口調で生成(§4)。
- ユーザーは返信にさらに返信でき、その場合は同じペルソナが会話を続ける(スレッド形式)。

### 3.4 画面(v1)
1. **タイムライン**: 自分のつぶやき+付いたリアクション・返信
2. **フォロワー一覧**: 20人分のカード(フォロー済みは通常表示、未フォローは「???」のシルエット)
3. **プロフィール詳細**: 名前・ID・年齢・職業・自己紹介・好きな話題・最近のやりとり
4. **通知**: 新規フォロー・いいね・返信

### 3.5 将来拡張(v2以降の候補)
- フォロワー同士の会話(同じ話題で盛り上がる / 意見が割れる)
- 放置するとフォローが外れる(リムーブ)、久々の投稿で戻ってくる
- フォロワー自身の「つぶやき」がタイムラインに流れる(自分のTLが賑やかになる)
- 画像付き投稿、DM、ハッシュタグ、フォロワー数のグラフ

## 4. フォロワー(ペルソナ)設計

### 4.1 ペルソナのデータ項目

| 項目 | 内容 |
|---|---|
| id / 表示名 / @ハンドル | 例: `kenji_run` |
| 属性 | 年齢・職業・住まい(ざっくり) |
| 性格 | 3語程度(例: 熱血・世話好き・単純) |
| **関心トピック** | `strong`(強い関心)/ `mid`(中)/ `weak`(弱)/ `dislike`(苦手)をタグで保持 |
| **口調** | 一人称、語尾、口癖、絵文字の頻度、敬語/タメ口、方言、禁止表現 |
| 気難しさ `θ` | フォローの閾値(高いほど簡単にはフォローしない) |
| 反応傾向 | いいね率・返信率・文章量(短文/長文) |
| 活動時間帯 | 返信が返ってくる時間の演出用(任意) |
| 口調サンプル | 実際のセリフ例を3〜5個(LLMへのfew-shot用) |

### 4.3 口調の維持ルール
- ペルソナごとに **システムプロンプトの口調ブロック** を固定し、毎回同じ定義を渡す。
- 返信は **ペルソナの文章量設定** に従う(例: ショウは1文、トオルは3文)。
- 禁止: 全員が同じ文体になる / 丁寧な「AIっぽい」定型文(「素晴らしいですね!」の連発)/ 他人を攻撃する内容。
- 過去の返信を直近N件(5件程度)プロンプトに含め、口癖と話の継続性を保つ。

## 5. 仕組み(ロジック)

### 5.1 全体フロー

```
つぶやき投稿
  │
  ① 話題解析(LLM) ── トピックタグ+重み、感情、固有名詞を JSON で出力
  │
  ② フォロー判定(ルールベース+乱数) ── 候補プールの各ペルソナの親和度を計算
  │       → 最大3人が新規フォロワーに
  │
  ③ リアクション判定(ルールベース) ── フォロワー全員について 無視 / いいね / 返信 を決定
  │
  ④ 返信生成(LLM) ── 「返信する」と決まったペルソナ分を1回のJSON出力でまとめて生成
  │
  ⑤ 表示 ── 時間差(数秒〜数分)をつけて順次タイムラインに出現
```

### 5.2 ① 話題解析
- 入力: つぶやき本文
- 出力例:
  ```json
  { "topics": [{"tag": "料理", "weight": 0.7}, {"tag": "節約", "weight": 0.3}],
    "sentiment": "positive", "intensity": 0.6 }
  ```
- タグは固定の語彙リスト(§4.2 の関心トピックを網羅)から選ばせ、揺れを防ぐ。

### 5.3 ② フォロー判定

```
親和度 affinity(f, 投稿) = Σ ( 投稿のtag重み × ペルソナの関心値 )
  関心値: strong=1.0 / mid=0.5 / weak=0.2 / 未設定=0 / dislike=-0.5

フォロー確率 P = sigmoid( a × ( affinity − θ_f ) ) + 知名度ボーナス
  知名度ボーナス: 現在のフォロワー数が多いほどわずかに加算(「人気の人にはフォローしやすい」演出)

特例: strongトピックが重み0.5以上で含まれる場合は P を高め(例: 0.9)に引き上げる
```
- 全候補の P を計算し、確率で当選した中から **親和度上位最大3人** を採用。
- 乱数のシードは投稿IDで固定し、再現性を確保(デバッグ・テスト用)。

### 5.4 ③ リアクション判定
- 親和度 ≥ 高閾値 → 返信、≥ 中閾値 → いいね(+低確率で返信)、それ未満 → 無視。
- ペルソナごとの「返信率/いいね率」で最終確率を補正。
- 1投稿あたりの返信は **最大5件** に絞る(画面が埋まらないように)。

### 5.5 ④ 返信生成(LLM)
- 入力: ペルソナ定義(口調ブロック)、つぶやき本文、話題解析結果、直近のやりとり、「新規フォロー時か」フラグ。
- 出力: `[{persona_id, text, mood}]` のJSON(複数人まとめて1リクエスト)。
- 出力後に検証: 文字数、禁止表現、口調チェック(語尾・一人称のルールベース検査)。違反時は再生成(最大2回)。

## 6. データモデル(案)

| テーブル | 主なカラム |
|---|---|
| `personas` | id, name, handle, profile(JSON: 属性/性格/口調/サンプル), interests(JSON: tag→level), theta, reaction_profile |
| `posts` | id, body, topics(JSON), sentiment, created_at |
| `followers` | persona_id, followed_at, trigger_post_id, affinity_at_follow |
| `reactions` | id, post_id, persona_id, type(`like`/`reply`), text, created_at |
| `threads` | reply の親子関係(ユーザー返信への再返信) |
| `notifications` | id, type, ref_id, read, created_at |

- ペルソナ定義は `personas.json` として静的管理し、起動時にDBへ投入(キャラ調整をファイル編集で行えるように)。
- 保存先: SQLite(ローカル1ユーザー前提)。

## 8. 非機能・安全面

- 画面上に「登場人物はすべてAIによる架空の人物です」と明記する。
- 実在の人物・団体・SNSの名称やブランドを模倣しない。
- 攻撃的・差別的・性的な内容はプロンプトと出力検査の両方で抑制する(アンチ/荒らし役は v1 では入れない)。
- ユーザーの投稿データはローカルDBのみに保存。LLM送信は話題解析・返信生成に必要な最小限(個人情報の入力は注意喚起)。
- LLM障害時は定型リアクション(いいねのみ)にフォールバックし、アプリは止めない。

## 9. 開発ステップ(案)

1. **M1**: ペルソナJSON(20人)作成+話題タグ語彙の確定
2. **M2**: 投稿 → 話題解析 → フォロー判定(返信なし、数値のみ表示)で増え方を調整
3. **M3**: 返信生成+口調検証、タイムライン/フォロワー一覧UI
4. **M4**: 通知、スレッド会話、時間差演出
5. **M5**: 調整(フォロー確率・返信頻度・口調の個性が出ているかの確認)、テスト
